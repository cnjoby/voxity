## 2. P0：M1 必做任务

### SNR-001｜冻结统一消息、动作结果及分项授权

执行状态：代码验证完成，后端已随 SNR-003/004 部署；Schema、跨端 fixture、旧库迁移与消息访问投影均已实现，证据见[实现记录](../development/snr-001-002.md)。

- **负责人／规模：**产品架构 + 后端 + 终端负责人，M。
- **依赖：**本文与产品架构；无外部系统依赖。
- **实施入口：**`server/app/models.py`、`storage.py`、`schema.sql`；`docs/development/contracts.md`；Android `Models.kt`、ESP32 交接协议。
- **交付：**版本化的 `VoiceMessageView`、`AgentTurnResult`、`SessionCapabilities` JSON Schema／等效验证模型及正反 fixture。先实现统一读投影，保留现有写接口和 `kind`。
- **读模型：**六要素；`source_type` 与 `content_origin`；`visibility` 与 `recipient_ids`；`conversation_id`、父消息和原请求引用；观察时间未知可空。旧 `root_question_id` 可以适配真实 question / scene 根，不丢旧 ID。
- **动作结果：**区分私有信息回应、需澄清、已建问人任务、已发布、私聊、真人交流、忽略、暂缓、结果未知；模型不能填可信用户、运营资格或伪造消息 ID。
- **分项权限：**私人信息查询、向真人发问、自动分享现场原声、在明确线程回应、找车友、自动播放分别表达。初始均无新增授权；自动分享不隐含找车友或发布私人问题。用户明确要求问人时，在有效会话和已告知范围内执行，不逐条再确认。
- **兼容：**旧 `auto_publish/auto_play/network_enabled` 保留原含义；旧会话不推定取得新权限。需要新能力的旧端返回可理解的不可用结果，不静默扩大权限。
- **验收：**同一个真人运营公告可同时表示「运营来源 + 真人录音」；参与者交流不外泄到 public；未知观察时间不变成录音时间；旧请求 fixture 正常解析；缺少任何对应许可都不产生副作用。

### SNR-002｜统一语音意图编排，解除私人查询与公开授权耦合

执行状态：本地代码验证完成，并通过两项 Android 隔离模拟器检查；HTTP/MCP 共用执行方法、私人查询与公开授权分离。后端公网与重启验证已随 SNR-003/004 完成；实际供应商与真人车内验收待后续阶段，见[实现记录](../development/snr-001-002.md)。

- **负责人／规模：**后端 + Android／Linx 接入，L。
- **依赖：**001。
- **实施入口：**`agent.py`、`exchange.py`、`main.py`、`mcp.py`；Android `ExchangeService.kt`、`LinxSession.kt`。
- **现状：**目的地澄清、路况／天气工具、远程问人和真人闲聊已有实现及隔离用例；不要重写这些功能。现有自然发言提交与完成复核统一要求 `auto_publish`；Android 设置 `network_enabled=publish`。私人查询因此仍依附公共交流会话。
- **交付：**一个应用层命令入口，由 HTTP 与 MCP／Linx 适配调用；同一用户和意图使用同一授权、地点消歧和任务规则。携带原声引用的公共操作必须证明本轮原声来源，纯文本工具调用不能冒充真人原声。
- **语义：**区分「查一下路况」「问问现场的人」「我刚看到堵住了」「回复刚才那位」「找车友」「和 AI 聊天」。优先复用现有确定性分类，增加结构化回退；不以单个“还有／天气”等关键词覆盖明确回答上下文。
- **澄清：**保存原始需求、原声、待补字段、目标候选、原授权版本和截止时间。澄清回复只补缺项，不把「上海世纪公园」作为新公共正文；迟到结果不得套到新任务。
- **验收：**仅授权私人查询可以查地图且不生成公共 post；明确问人可从远处建任务；「前面景区」缺导航上下文时只澄清，不能投到会话地点；原先的 question / answer / scene 线程回归保持通过；相同语义通过两个入口得到相同权限与目标，缺原声的入口清楚说明执行限制。

### SNR-003｜统一合法信息检索与来源选择

执行状态：代码验证完成、后端已部署。共享权限／时效检索、私人来源选择、播放前来源复核及 feed/queue 兼容已实现；真人与现场效果未验收，见[实现记录](../development/snr-003-004.md)。

- **负责人／规模：**后端 + 产品，M。
- **依赖：**001；与 002 共享动作合同。
- **实施入口：**`voices.py`、`service.py:get_feed`、`agent.py:query_agent_tool`、`mcp.py`、`geo.py`。
- **现状：**公告、知识、现场 scene、授权频道已存在；私人助手 `get_feed` 仍限 question / answer。天气和路线工具已加入工作区。
- **交付：**一个有权限、有时效的检索应用方法，供主动地点查询、私人助手和自然交流调用；结果携带来源、观察／更新时间、适用范围、有效版本与未知项。保留现有各类访问校验，不能简单扩大 SQL `kind` 列表就结束。
- **选择：**停车问题先取适用的当前停车公告与新鲜观察；历史知识不当实时状态；路线查询用路线数据；用户明确要问现场时建立协作任务。多个合法来源可以列出差异，不能用一个统一排序分数覆盖权限、事实范围或用户明确意图。
- **回退：**工具失败仅提供可用信息或建议问人；未授权时不自动公开。无人／无数据分别记录，避免把返回空列表解释为「现场没有车位」。
- **验收：**被撤回、替代、过期、其他频道越权的内容均不出声；同一声音多入口命中只交付一次；区县天气、道路未知段保持原有边界；运营公告与用户观察冲突时分别保留时间和来源；用户拒绝问人后没有公共副作用。

### SNR-004｜补个人任务台账、有限协作路由与结果核对

执行状态：代码验证完成、后端已部署；Android 本人任务面板与原 UUID 恢复通过隔离模拟器。已有回应／已听完／明确解决分离，有界邀请、任务隔离与取消竞态通过，见[实现记录](../development/snr-003-004.md)。

- **负责人／规模：**后端 + 终端，L。
- **依赖：**001、002；消费 003 结果。
- **实施入口：**`service.py`、`exchange.py`、`chat.py`、`schema.sql`、`storage.py`；Android `TaskStore.kt`、`AckReconciler.kt`。
- **交付：**增量的个人任务记录／投影与本人查询能力；从轮次／原请求幂等标识查到实际提交结果，即使客户端未收到 `turn_id`。任务关联公开问题、工具结果、邀请、对话与回答，用户私有目标不直接公开。
- **Agent 协作：**在既有 invitation / delivery 上明确 task / request / deadline / visibility / version；每位接收者按自己的规则处理。分发批量、最大邀请数、冷却和等待截止时间可配置；同一请求不因轮询或暂缓反复邀请。首版无回答时到期返回真实结果，不自动无限扩散。
- **状态：**收到首个回答保持旧 question 的 answered 行为兼容，但个人需求只到「已有回应」；追问沿真实线程。M1 暂保留一个活跃现场提问，第二个需求明确提示或私有暂存，不伪装已发布。
- **恢复：**未知发送查原请求，不更换 ID 重发；取消与暂停使未提交旧动作失效；自己离开起点后仍能等待合法回复。原声缓存、任务引用和删除／保留期限一致，不承诺永久可听。
- **验收：**两用户的相同目标生成独立个人任务；A 取消不关闭 C 的任务；无回应正常超时；模型／地图迟到不重启任务；ack 重试不产生重复播放；已收到未听完不标已解决；任务页和服务端最终状态一致。

| SNR-105 / P1，开放陌生人前完成 | 运营资格核验／撤销、普通用户举报／拉黑、滥发限流、独立内容审核状态、最小审计与数据删除流程；先为受控 POI 做管理工具 | 001、004；产品／运营 + 后端；L | 用户观察不能冒充公告；撤销运营资格阻止新发布并处理待播；拉黑影响新邀请；审核决定不能替代事实核验或个人收听许可 |
| SNR-106 / P1 | 可观测性：全链路 task / turn / message / delivery ID；分来源等待时间、成功／失败分母、打扰次数与按需成本；最小化日志 | 002–004；后端 + 测试；M | 从一个失败需求能定位断点；无回应计入分母；音频生成、交付、开始、听完与解决分别统计；不记录 Token 或公开原始定位 |

101 的最小字段冻结可随 001 做；实际事件归并和多回答在 M1 稳定后实施。103 中现有公告版本机制沿用，新增的是跨检索／任务／事件投影的一致失效。105 在受控演示阶段可用人工授权与受控供给，不宣称具备完整开放社区治理。

## 4. M3：真实试点与 ESP32 任务

### SNR-201｜一个 POI 的封闭试点

- **依赖：**M1 验收；101、103、105、106 的试点必要范围；需要一个实际授权运营方与自愿参与者。
- **负责人／规模：**产品／运营 + 集成，外部依赖决定排期。
- **交付：**明确 POI、入口和实际可识别范围、运营身份、公告维护责任、参与者、试点时段、成功指标与退出方式；记录每个有效需求和失败。
- **验收：**物理到达而非注入坐标；公告更新／撤回／过期和静音对照；真实远程问人及原声回传；观察实际有用性与打扰情况。二维位置不验证楼层，前台会话结果不证明锁屏可达。
- **业务结果：**是否有人持续使用、是否减少实际未知、运营方是否愿意继续试点。没有付费证据时只记录意愿和反馈。

### SNR-202｜ESP32 对齐统一能力合同并分项验收

- **依赖：**001、002、004；硬件成员提供板卡、固件和可复现环境。
- **负责人／规模：**固件／硬件 + 服务端接入，L。
- **实施入口：**`docs/development/esp32-ai-handoff.md`、`docs/development/esp32.md`，服务端兼容接口。
- **交付：**设备身份、权限、自然短句采集、原声和 Agent 回应区分、任务／线程上下文、播放前校验、幂等回执、安静与关麦；无法支持的能力明确返回不可用。
- **验收：**真实拾音、VAD、AEC、播放中开口、断网本地停止、长期连接／重启不续发；同一账户换主终端不双播。不假设能感知另一部手机来电或导航，不用 Android 结果代表固件通过。

## 5. P2：由试点证据触发

| 候选 | 启动条件 |

## 6. M1 固定验收场景

| ID | 输入与前提 | 可验证结果 | 代码／设备证据 |
| --- | --- | --- | --- |
| A01 私人查路况 | A 只允许私人查询，说「去张江人工智能岛现在堵不堵？」 | 给有来源和时间的路线信息；公共 post、车友邀请均不增加 | API／MCP 一致用例；手机真实语音 |
| A02 私人与真人闲聊 | 明确「和 AI 聊聊」／「找个车友聊聊」；后者先无匹配再双方自愿 | 私聊不公开；不把在线互助当闲聊同意；真人与 AI 切换不无声替换对象 | 独立意愿、第三方访问测试；双人设备 |
| A03 地点澄清 | 「前面景区还有位吗？」但没有确定导航上下文 | 只澄清，不发布到预选地点；补地点后仍保留原问题原声与授权 | 查询前后持久化快照；手机澄清两轮 |
| A04 有效信息先答 | 有当前停车公告与过期现场观察 | 当前公告带来源／时间，旧观察不当作现在；不产生无必要重复问题 | 检索与版本 fixture；实际播音 |
| A05 明确远程问人 | A 在远处明确问一个 POI；B 在现场且愿意 | 正确任务和邀请；B 自愿原声回 A；不要求 A 在目标附近 | 既有远程用例扩展；双人真实录音 |
| A06 分享与接话 | B 分享现场观察，A 听后追问 | scene 为真实根；没有合法上下文不伪造 reply；与同地 C 的问题不串 | 线程／权限测试；双人原声 |
| A07 安静／关麦 | 正在播音、网络不可用、模型仍处理中 | 本地立即停声；安静暂停自动操作，关麦结束；迟到结果不继续执行 | 竞态测试；设备离线对照 |
| A08 未知发送与重试 | 提交已落库但响应丢失，或 ack 丢失 | 用原请求核对真实结果，不能换 ID 重发；同一声音不自动重播 | 丢响应测试；设备网络恢复 |
| A09 无人回应／取消 | 所有合格对象无回应；或 A 提前结束 | 真实超时／取消，不能生成 AI 现场答案；C 的独立任务不受影响 | 可控时钟测试；设备任务状态 |
| A10 公告与声音失效 | 下载／排队后公告被替代、撤回或到期 | 播放前拒绝旧版本；旧缓存不自动恢复 | 服务端复核；设备中途更新 |
| A11 资格与位置 | 手选 POI、精度过低、定位过时、方向未知、楼层未知 | 可问目标地点；不伪称在场／同向／B2，不获得运营身份 | 位置与权限反例；现场到达另验 |
| A12 来源及声音边界 | 真人、运营、工具 TTS；广播／乘客／回声／超长发言 | 来源真实可辨；不能证明来源的录音不自动公开；超长内容不截断公开 | 音频单元／设备测试；车内声学结果另记 |

M1 可用的最小判断是 A01、A03–A11 在选定 Android 设备和当前受测范围通过；A02 与 A12 中未通过的可选能力必须关闭或保持私有，并如实限制产品承诺。若要对外宣称自动车内采集可用，A12 的相关真实声源与声学项必须通过。ESP32 全部单列，不能通过缩减测试措辞视作已交付。

## 8. 执行后更新方式

每个任务完成后在对应实现文档记录版本、环境、命令、通过与失败、未验收部分，并在本表关联结果。产品行为改变时先更新架构基线和契约，再更新设备交接；历史实测记录保留日期，不用今天的新实现重写昨天的结果。阶段完成由可观察验收决定，不由文档中的任务勾选推定。
