# 声呐 Sonar｜BP 路演内容提纲

版本：2026-10-25，待审阅。目标：黑客松评委；建议 12 页主讲，约 5 分钟，含 60 秒核心演示。此文件为内容重组稿，本轮未改写现有 PPTX。

## 讲述原则

主线：**一次真实需要 → 一条现场回答 → 一个可控的语音入口 → 一个可验证的商业起点。**

每页回答一个问题，屏幕保留结论与场景，接口与验收细节移入附录。事实标来源，原型和目标体验分开；商业假设在页面以“待验证”标记，详细备注保留 `[ASSUMPTION]`。

## 01｜听见同路的声音

**要让评委记住：声呐让车主听见现场的人，也让地点信息找到需要它的人。**

上屏：声呐 Sonar；“听见同路的声音”；副句“以车内免提语音，连接人、车、地点与事件”。

画面：车内一个问题，一条连接到停车场或路口的声音。开场说：“到了景区，你最想知道的，可能只是另一边的停车场还有没有位。”用具体需要进入产品，社区愿景在后文展开。约 10 秒。

## 02｜车到了，信息还没到

**要让评委感到：最需要现场信息时，司机很难方便地问到人。**

上屏三个场景：

| 场景 | 车里会问的一句话 | 没有答案的代价 |
| --- | --- | --- |
| 景区停车 | “这个入口排满了，哪个停车场还能进？” | 继续绕行、排错队 |
| 事故后方 | “前面开始通了吗？刚经过的人能说一句吗？” | 等待中缺少判断依据 |
| 拥堵路口 | “红线还在，车流现在动了吗？” | 接人和到达安排难以判断 |

画面：三张现场照片或简洁插画，问题大于说明文字。备注注明“演示情境，非访谈原话”，不使用虚构用户数据。约 25 秒。

## 03｜答案可能就在附近，问题还没问到他

**要让评委理解：声呐要验证的是具体现场问题的供需连接。**

上屏：“信息可能在刚经过的车主、前方乘客、停车场工作人员那里。”下接三步：找到合适的人 → 对方愿意说一句 → 回答回到提问者。

备注：地图已有路况等能力，群聊也能沟通；声呐聚焦按地点、事件与回应意愿连接，并替发问者保留等待。Zello 已有语音频道，Waze 已探索自然语言路况上报，避免“行业空白”表述。参考见补充材料。约 20 秒。

## 04｜人发声，广场组织，Agent 替你等

**要让评委理解：城市声音社区如何运作。**

上屏三角色：

- 人：提问、自愿回答、分享；授权运营方发布地点告知。
- 声音广场（公共讨论空间）：保存原声，组织地点、事件、时间与问答关系。
- 个人 Agent：筛选提醒、安排收听、追踪回复，尊重安静。

画面：同一张位置图上标出提问车、回应者和停车场节点；用一条带时间与来源的语音卡串起三者。即时需求可以异步回答，离开提问位置仍能等待自己的有效回复。当前为单服务器原型，产品“分布式”的含义限定为多来源、多地点参与。约 20 秒。

## 05｜演示：一句“哪边有位”，找到一个愿意回答的人

**要证明：提问、匹配、自愿回答、原声回传形成闭环。**

上屏只放四步：A 提问 → B 收到相关邀请 → B 自愿回答 → A 听到原声。旁边保留“安静”对照。

演示脚本：

| 时段 | 操作与可见结果 |
| --- | --- |
| 0–10 秒 | 展示 A、B 及目标停车场。使用注入坐标时，屏幕持续标“模拟位置”；设备前台在线。 |
| 10–25 秒 | A 问“景区东停车场现在还能进吗？”按当前已验收的发布路径执行；B 处在有效目标范围且愿意互助。 |
| 25–40 秒 | B 收到邀请并自愿录音：“我刚从东入口出来，入口还在排队；西入口我没有看到。”保留观察范围。 |
| 40–50 秒 | A 收到对应原声，展示回答者、地点与时间；无回复时展示等待状态。 |
| 50–60 秒 | 开启安静后再产生邀请，验证不主动出声；自己的回复可保留待听。 |

上述脚本为待彩排方案。若真人公开链路未验收，使用标明测试条件的回放；合成测试音频标“合成”，不充作现场真人。会话授权后的自动交流是最新目标设计，尚待实现；现有确认步骤不剪成已完成的自动体验。约 60 秒。

## 06｜AI 负责整理和判断，现场的人负责说出所见

**要让评委看见：快速决策模型与 LLM 各有边界。**

上屏流程：语音转写 → LLM 整理语义与候选 → 规则门禁＋独立决策 → 合适的人收到邀请 → 真人回答回传。

| 模块 | 作用 | 状态与边界 |
| --- | --- | --- |
| 确定规则 | 权限、授权、位置、时效、静音 | 交付前后均需校验 |
| 内容审核决策 `[ASSUMPTION]` | 内容分类；通过／拦截／待复核 | 待建立专门策略与评估集，不能用提醒模型的结果代替 |
| 注意力决策 | 提醒／暂缓／忽略 | 项目文档记录已接入邀请筛选，尚需真人体验评估 |
| LLM | 整理地点、事件、意图，辅助匹配与摘要 | 保留原声及来源；缺失事实不生成答案 |

备注：决策模型也可以是训练后的大模型；“快”是待实测的效果，不能写成已有毫秒级指标。内容审核通过不证明车位或事故描述属实。约 25 秒。

## 07｜先服务一个地点，再连接更多需求

**要让评委看见：商业场景有先后，且共用明确的用户需要。**

上屏四段路径，标“建议，待验证”：

1. 现场互助：证明车主愿意问、有人愿意答。
2. 认证 POI：补充稳定供给，验证运营方是否愿意付费。
3. 品牌服务：用户主动提出需求后，连接服务方。
4. 拼车／用车：在供需与履约可验证后探索撮合。

备注：这是商业验证顺序，不改变已有产品三类声音定义。景点感慨、解说等情境声音仍是社区内容扩展，当前不单独承诺收入。约 15 秒。

## 08｜第一笔钱的验证：让停车场的一句话，找到正要进场的人

**要让评委理解：为什么有人可能付费。**

上屏故事：“运营方更新：B2 车位紧张，请前往 B3。”→ 车到入口，在允许收听时听到带来源和时间的一次提示 → 用户可追问或静音 → 旧公告到期或被更新后撤下。

上屏付费假设：**POI 运营方为公告发布管理、到达交付与服务效果付费。**候选买方为停车场、景区或物业的实际运营及预算负责人，尚未确认。

画面：运营后台一张有效公告，连接车内一条声音卡。用效果指标支撑价值：合格会话实际听到情况、过期／重复提示、重复问询变化、报价与试点反馈。

备注：认证证明主体与管理权限；真实动态车位仍需要更新来源。当前只可靠定位到停车场附近时，不声称识别 B2／B3 楼层，不保证 B3 有位；公告不会强行越过静音。该场景已有前台原型扩展，实体到达与商业试点待验收。约 25 秒。

## 09｜我们已经有入口基础，下一步把声呐接进真实试点

**要让评委区分：团队已有资源与声呐尚待建立的落地证据。**

上屏两列：

| 已有基础 | 下一步证据 |
| --- | --- |
| xAtom 智能硬件、灵矽语音能力（用户确认） | 完成声呐业务链路与车内体验验收 |
| 主机厂对底座的合作意向（用户确认） | 明确声呐试点车型、接入范围与负责人 |
| 问答、POI 公告与个人提醒原型（项目文档记录） | 真人公开问答、实体到达与实际使用数据 |

备注：不展示虚构客户 logo、不填车辆装机量；涉及对外披露合作方身份时以实际可披露范围为准。现有优势是开发与洽谈基础，尚未形成声呐的分发壁垒。约 20 秒。

## 10｜商业模式：先验证付费服务，再扩大连接价值

**要让评委理解：谁使用、谁供给、谁可能买单。**

上屏三条假设：

- 近期：POI 运营方购买公告管理与到达服务；测试试点服务费／订阅。
- 接入：主机厂或集成方的集成与运营服务，另行确认采购方和合同范围。
- 后续：品牌服务与出行撮合，在明确用户需求、履约和归因后测试服务费／分成。

车主是使用者；车主与授权 POI 提供内容；主机厂可能是渠道、集成客户或双方，须以实际合作为准。当前无付费数据，页面不填营收预测、未经核实的 TAM 或虚构客单价。

备注：商业内容标来源，主动服务请求与公共管理公告分开；持续无关播报会损害用户信任。约 20 秒。

## 11｜用一个地点，验证用户价值和付费价值

**要让评委相信：团队知道下一步如何证伪。**

`[ASSUMPTION]` 建议试点：一个停车场／景区入口、一位授权运营负责人、一组同意参与的车主。样本量、周期、预算与通过门槛在试点前确定。

| 要验证的假设 | 测量与证据 | 不成立时如何调整 |
| --- | --- | --- |
| 现场问题能等到有用回答 | 有效问题数、获真人回复比例、首个回复时间；无回复也计入 | 收窄地点／时段，优先补运营方回应 |
| 公告确实被需要的人听到 | 符合范围的前台会话数、实际收到与听完、跳过／关闭 | 调整触发与提示；保留主动查询 |
| 交付可控且可信 | 过期／重复／静音违规记录、来源与时间展示 | 修复规则后再扩大范围 |
| POI 有付费理由 | 可比时段的重复问询记录、报价反馈、付费试点与续用 | 调整交付价值或停止该收费假设 |

备注：送达、听完与真正理解分别看待；收到回复与回答正确也不等同。统计 API 成功数不能替代用户效果。约 25 秒。

## 12｜让每一次“前面怎么样了”，都更有机会得到回答

**要让评委记住价值，并知道项目需要什么。**

上屏回到停车问题，再出现一个带时间与来源的回答。落点：“先把一个地点做有用，再把更多地点连起来。”

`[ASSUMPTION]` 合作诉求：一处可试点的 POI、一位运营负责人；与已有主机厂关系确认声呐验证范围。当前没有用户确认的融资额度，不新增融资诉求。

演讲结束保留“听见同路的声音”。约 15 秒。主讲预计 4 分 40 秒，另留约 20 秒切换余量。

## 附录：回答评委追问

1. **MVP 范围与现状**：双用户问答为主验证；服务端／模拟器／手机私人语音／实体车内分别列证据；POI 扩展已有原型，真人与现场待验收。
2. **决策与 LLM 技术链路**：ASR、语义结构化、确定规则、独立内容审核与注意力任务、MCP 工具、原声存储；标清已接入和拟验证。
3. **失败与安静**：无人回应、含混输入、模型暂缓、公告过期、断网、静音与授权撤销；无依据不生成现场结论。
4. **未来场景**：品牌维修／救援服务先确认需求与履约方；拼车明确出发地、目的地、时间、意愿，再交合适合作方。情境声音保留来源和录制时间。
5. **竞争与证据**：Zello、Waze、高德及现有群聊／POI 广播的能力边界；比较方法见补充材料，避免“唯一”“行业首创”。
