# 远程地点作为路线起点：2026-10-26

## 现场与根因

Android 0.3.1 用户已选模力社区。生产031现场只读核对：Alice 的 profile 与当前会话均为 `B0K2KHYN77`，来源 `remote_place`；坐标与注册 POI 相符，采样距核对约6秒。此前查询金科路与高科中路交叉口的轮次确实返回 `location_required`。

位置已经传到服务端。问题在 `query_agent_tool`：路线起点只接受 `android` 和已允许的 `android_mock`，排除了有效的远程地点。它与已有远程地点选择行为不一致。

## 修复与合同

- 路线允许使用本人选定且有效的 `remote_place` 作为起点，继续检查采样时效、精度及坐标完整性；其他用户的位置不能代为补足，旧模拟来源也不会被当作有效定位。
- 远程路线回复明确说“从你选择的远程地点××出发”。来源字段增加 `origin_place_id`、`origin_place_label`、`origin_source`，不返回原点的精确经纬度。
- 远程地点仍为远程来源，不制造手机实到、GPS 定位或新的现场资格；查询不改变本人或他人的位置，不发布真人声音。
- 缺少有效起点时，提示取得定位或选择远程出发地点。MCP 路线工具说明同步更新。
- Android 无需升级；当前0.3.1可直接使用。灵矽配置、核验名单、设备身份和凭证均未修改。
