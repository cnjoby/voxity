## 已修复问题

| 问题 | 修复 | 回归证据 |
| --- | --- | --- |
| 云端识别“刚才那句别发”丢失上一条发布对象，并把识别 Job 当作未结束上传 | 控制分类先于清除上一条发布结果；独立跟踪真实 uploadInFlight；本地控制不等待云端 STT/HTTP | Android 设备检查：识别 Job 活跃时仍真实请求撤回上一条 scene |
| 播放尚未开始便绑定回复上下文 | 最终 mayStart 检查后才启动 MediaPlayer；只在 onStarted 回调写入已听上下文；串行化上下文写入，未同步的后续发言保持私有 | Android 设备检查：播放前取消不触发上下文回调；会话及打断检查 |
| answer 的消息 ID 被误当作对话根，导致后续 reply 消失 | 当前上下文通过真实 exchange_root 解析，发布 answer 后保留当前任务 | 服务端自然提问、回答与后续回复用例 |
| 切换话题后旧回复/旧批准场景继续自动播放 | 自动回复仅关联当前任务根；语义批准交付记录判定时上下文；旧项保持待听 | 服务端上下文切换用例，旧交付保持 pending |
| 新场景模型调用拖住已到达的直接回复 | 先返回当前任务可播放原声；直接回复优先排序 | 服务端断言存在直接回复时不会调用新候选模型 |
| 问题发布后，另一自然模式用户听不到真人问题 | 对已批准的真实 invitation 交付问题原声，保留邀请、时效、位置、访问与相关性检查，不播放系统邀请控制声音 | 服务端断言 question 音频可取得且后续回答/回复关联正确 |
| 最新十条被跳过的候选永久挡住后面的有效声音 | 流式越过不合格候选，不在规则过滤前截断固定页 | 十条撤回声音不能阻挡较早有效场景的回归用例 |
| 客户端延后项仍 pending，可能挡住新候选调度 | 客户端发送已尝试/延后 delivery ID 排除列表（最多 256）；服务端只过滤本人的自动队列，不删除交付 | 服务端延后排除与新候选用例；设备检查验证实际请求携带 exclude |
| 同时存在多个邀请时，已听问题仍无法回答 | 优先选择与当前已听 question 匹配的真实邀请；无明确上下文才要求唯一邀请 | 服务端多问题/多邀请回归用例 |
