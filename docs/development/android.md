# Android AI 任务包

状态：全部待开发。角色预算：D1 8h，D2 实现与自检5h、联合验收3h。

先读[架构](../design/architecture.md)、[契约](contracts.md)及[总计划](../../two-day-development.md)。默认 alice 为提问者；Android 同时应能收邀请并回答，以便两端互测。

## 目录、界面与边界

只拥有 `android/`。若已有工程沿用技术栈；当前无工程时默认 Kotlin + Compose + OkHttp，SDK/Gradle 版本依据实际本机环境固定并记录，不为接入另写混合应用。区分 SonarApi、LinxSession、AudioCoordinator、TaskStore，设备配置不硬编码真实 Token。

单屏任务卡足够：连接状态与“模拟位置”标识、问附近的人、录音与确认、问题等待/回答、原声播放、互助/静音；收到邀请时显示回应/拒绝。预设一个目标路口。永久位置后台服务与地图不在范围。

## 任务

- [ ] **A1｜工程与双链路接入，D1 0–2h**
  - 工程可构建安装；注入 Sonar URL、设备凭证、Linx 绑定配置；申请麦克风权限，拒绝时明确反馈。
  - Linx 设备注册/WSS/手动录音跑一轮真实语音；记录 STT 与 TTS 事件、协商格式及结束条件，不记录凭证。
  - SonarApi 可 GET me；支持显式 mock/live 配置，mock 显示“模拟接口”。
  - 验收：构建成功与真实手机录音分别给证据；注册/编解码不通立即记录，不等到第二天。

- [ ] **A2｜提问与确认公开，D1 2–5h**
  - 选择目标路口→短录音→本地 WAV 与本轮 STT 关联→确认页→上传草稿→本人确认发布。
  - 持久保存 client_request_id 与草稿ID；上传重试沿用ID；不确定 STT 归属则不发布。
  - “录音”“上传”“待确认”“等待回答”可区分；确认失败保留草稿信息，禁止二次误发。
  - 验收：对样例接口跑通页面，再用实际服务器上传真实原声，能由返回的问题ID恢复任务。

- [ ] **A3｜等待、回复与声音播放，D1 5–8h**
  - 查询本人问题和 inbox；展示来源、时间、等待/已答/过期；收到回答下载原声，播放前复核 delivery。
  - 串行系统提示与原声，不与录音或 Linx TTS 重叠；完成后回执，静音只保留待听不结束提问。
  - 实现收到邀请后的回应/拒绝，reply_to 与 invitation_id 从当前任务绑定，不能让用户手填ID。
  - 验收 G1：A 的问题在 B 设备提示；B 回答后 A 听原声；“已回答”与“已播放”分开显示。

- [ ] **A4｜个人意愿与恢复，D2 0–3h**
  - 开关直接调用 context；自然语言“现在安静”经 Linx set_focus 改变同一配置，回读确认。
  - 静音立即本地执行；开启声音须同步成功；revision 冲突重读。停止当前播放与取消问题分开。
  - 出声前记已尝试项，播完持久化回执再同步；重连先 GET me/问题/inbox，崩溃恢复不自动重播不确定项。
  - 无 TTS 开始、断连或本地缓冲未空时有超时处理；邀请等到失效则丢弃，不能长期卡住。
  - 验收：录音中不插播、静音时不响、旧邀请不响，恢复后仅有效内容可听。

- [ ] **A5｜构建与实机自检，D2 3–5h**
  - 为任务状态与 AudioCoordinator 的录音/TTS/原声互斥添加少量单元检查；API 解析使用共享 JSON 样例。
  - 在实际设备执行上传/接收、失败重试、拒绝权限、网络切换和进程重启；没有实机时明确只完成模拟器检查。
  - 交付可安装 APK 路径、构建命令、配置方式、设备/系统版本和实际结果；不提供未经运行的“已通过”。

## 交给 AI 的执行指令

> 你负责 Sonar Android。读取总计划、架构、contracts.md 和本任务包，按 A1→A5 实施，只修改 android/ 与自己的执行记录。优先用共享 fixtures 完成交互，再切 live API；将 mock 与真实模式清晰标识。公开发言需要本人确认，手机只管理设备交互，个人策略归服务器。不要擅自改服务端字段。平台能力不明先做最小实测。最终交付 APK、运行方法、检查证据、未完成项，设备测试不能由编译成功代替。
