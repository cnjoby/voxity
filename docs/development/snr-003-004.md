## 统一检索与来源选择

`server/app/information.py` 提供共同检索和复核方法，供 HTTP、MCP、私人查询、目录及 feed 使用。先检验发布状态、原声访问权限、频道资格、撤回／替代、适用期及回答期限，再按用途选择来源。检索不会制造现场到达，也不会放宽原有音频下载权限。

- 支持公告、现场 scene、知识、answer/reply。停车先取适用公告和新鲜观察；历史知识、感想、适用性未知内容不能当作实时停车／天气／路况。回答可听期限较长时，动态查询仍受观察最大时效约束（默认 1 小时）。
- 返回来源类型、真人原声属性、作者／频道、地点、范围、观察／录制／发布时间、有效期和版本。未知观察时间保持空，不能拿录制时间冒充。多个来源分别引用其原文和范围，不生成统一现场结论。
- 私人停车查询有合法信息时直接回应，不新建公共问题；明确说“问问现场的人”仍走真人问答。天气优先区县工具数据，路线优先路线工具；失败只使用适用来源或提示可问人，不自动公开。工具来源保留边界及有效期（天气报告后 3 小时，路线查询后 60 秒），不保证 POI 实况或未知路段畅通。
- `get_feed` 可返回合法新声音类型；`queue_voice` 使用既有交付去重、权限和播放校验，同一原声跨入口不会额外生成一份交付。
- Android 在 TTS 合成后、播放前按来源 ID、用途和当前任务重新核对；已失效来源、已结束任务及已过期工具回应不自动出声。任务页展示历史结果时同时保留来源当前有效性。

首版用途和主题选择采用确定性规则，范围为明确地点及已有内容；不承诺任意语义搜索、事实真伪判定、入口／车道／方向识别或冲突自动裁决。“无合法信息”不是“没有车位”，有访问权限也不代表事实经过验证。

## 个人任务、有限协作与恢复

`server/app/tasks.py` 将发言、澄清、查询结果、问题、线程和本人交付关联到私有台账。旧已发布问题幂等补建个人记录，保留原问题 ID 和创建时间；不改写公共正文。不同用户或相同 POI 的独立需求不合并。沿真实上下文的追问可沿用任务。

| 状态 | 含义 |
| --- | --- |
| querying / clarifying | 正在查询／等待补充信息 |
| waiting | 已建立真人需求，等待回应 |
| responded | 已有工具或真人回应，尚未确认解决 |
| deferred | 暂未执行，保留实际原因 |
| resolved / cancelled | 本人明确确认已解决／结束 |
| timed_out / failed | 到期／失败；不能用 AI 编造现场结果 |

接收、播放与需求状态分开。`played` 不会变成 `resolved`；首个回答保留旧 question 的 answered 行为，但个人需求只变为 responded。任务动作要求本人身份、最新 revision 和请求 UUID；重复同一动作幂等，内容冲突或旧版本拒绝。结束发起者任务会关闭其线程后续交付；回应者结束自己的任务不能取消提问者待听音频。同地其他任务独立。结束个人任务不等同撤回已发布的独立 scene／知识／公告。

邀请仍复用已有 delivery 和个人筛选，增加 task/request/deadline/visibility/version 协作信息。默认活动批量 3、总邀请最多 10、批次冷却 30 秒，可由 `SONAR_INVITATION_BATCH_SIZE`、`SONAR_INVITATION_MAX_RECIPIENTS`、`SONAR_INVITATION_COOLDOWN_SECONDS` 配置。只在实际创建邀请后记录批次时间；同一问题不重复邀请同一人。无人时等待真实截止，不无限扩散。取消后外部模型／地图迟到结果不能继续提交。原有一个活跃现场提问限制继续保留。

Android 在上传前持久保存原 UUID、会话和原始请求信息；结果未知时只调用原请求查询，不换 ID 重发。核对不重播 TTS。请求日志最多 100 条，优先清理已有确定结果；未核对项保留。“我的”停车页显示任务、未知结果、来源和真实播放状态，提供刷新、已解决、结束任务。旧服务没有新接口时显示暂不可用，既有功能继续工作。

台账保存历史元数据和引用，读取时复核来源；音频生命周期仍沿用既有规则，不承诺永久可听。本轮未新增物理音频清理或用户删除策略，完整留存治理仍属后续任务。

## 增量接口

所有接口沿用当前用户鉴权，不能以输入 user_id 切换身份。详见[协议第 13 节](contracts.md)。

| 接口 | 行为 |
| --- | --- |
| POST `/v1/information` | `{place_id,query?,purpose?}`；返回 items/status/server_time |
| POST `/v1/information/validate` | `{message_ids,purpose?}`；返回 valid/valid_message_ids |
| GET `/v1/tasks`、`/v1/tasks/{task_id}` | 本人台账及当前合法来源、本人交付和历史结果 |
| POST `/v1/tasks/{task_id}/actions` | `{expected_revision,client_request_id,action:"resolve"或"cancel"}` |
| GET `/v1/requests/{request_id}` | 原 UUID 查询实际 turn/task 或旧草稿；不存在为 404 `REQUEST_NOT_FOUND`，无重发副作用 |

MCP 新增 `find_information / get_tasks / get_request / set_task_state`，共 12 个工具；HTTP 与 MCP 调用同一方法，云端可信映射不变。工具已部署不等于灵矽平台提示词已更新。`AgentTurnResult` v1 保持不变，旧轮次响应新增外层 `task_id`。老会话不默认获得新能力；原先未启用语音网络的固件仍可通过原本地问题路径处理“这里堵不堵”，不被强制切换成新私人查询。
