## 目录与设备交互

拥有 `firmware/`；若成员已有外部工程，先保留其框架，以适配层接入并记录对应路径，不覆盖现有固件。无板级源码时先实现可模拟的业务状态机和网络接口，板级录放接入由硬件成员完成，不能虚称已烧录。

板级适配职责：Wi-Fi/HTTPS、手动录音启停与 WAV 输出、Linx 协商格式编解码、播放/停止/缓冲排空事件、按键或现有交互输入。具体 API 随已有框架确定，业务模块不直接依赖某套引脚。

逻辑交互：空闲收邀请→短提示→“滴”→用户按键开始回复→停止录音→核对后确认上传发布；另支持拒绝、静音和停止。按键数量与短按/长按映射由硬件成员确定并文档化。没有屏幕时可回放本人录音核对，确认动作必须独立，不能录完自动公开。

## 任务

- [ ] **E1｜现有固件与双通道验证，D1 0–2h**
  - 确认已有工程能构建/烧录，连接 Wi-Fi 与 Linx 并完成一次语音往返。
  - 独立通过 Sonar Token GET me，播放实际格式的短 WAV，验证录音上限与缓存；平台音频按握手，Sonar 输出固定 WAV。
  - 单独注入平台与业务凭证；串口不打印密钥。
  - 验收：构建、烧录、真实录放分别有结果；无设备时以模拟适配器先开发后续模块并列出待接项。

- [ ] **E2｜轮询与主动提示，D1 2–5h**
  - 每秒读取 inbox；从统一 invitation 样例开始，识别问题ID、request_id、revision 和有效期。
  - 内置一个路口的系统短提示与“滴”，音频空闲时复核再播放，不要求 Linx 主动推送任意文本。
  - 提示后 ack alerted，保留 invitation_id 供回复；本地记录已尝试ID，重复轮询不重复响。
  - 验收：无“听新消息”操作也能因新问题提示；同一邀请轮询十次只提示一次。

- [ ] **E3｜真人回答与公开确认，D1 5–8h**
  - 将当前邀请锁定到唯一录音轮次；开始/停止录音，同时处理 Linx STT，超时或归属不明不发布。
  - 上传 multipart audio+metadata 成草稿，主人核对并独立确认后调用 confirm；缓存已上传草稿ID与 client_request_id，重试不重发。
  - 回答前复核邀请与位置；被取消或过期时明确反馈，不能把回复误发到新问题。
  - 验收 G1：真实设备提示后回答回到 A；早期可用标注素材测业务链路，最终必须替换真实录音。

- [ ] **E4｜音频互斥、意愿与恢复，D2 0–3h**
  - 一个 AudioCoordinator 管理 IDLE/RECORDING/LINX_TTS/PROMPT/VOICE_PLAYBACK；驱动报告缓冲排空，录音或 TTS 期间不插播。
  - 静音本地立即停止，再更新 context；支持 Linx set_focus 语音设置。停止原声 ack skipped；静音保留待听；拒绝邀请 ack declined。
  - 断网退避，重连先同步模式及任务；超时邀请丢弃，持久化已尝试/待回执项，断电恢复不自动重播不确定内容。
  - 验收：播放中静音立即停、录音中邀请延后或过期、无人回应不伪造回答；旧 request_id 不误响。

- [ ] **E5｜固件交付与实机检查，D2 3–5h**
  - 用模拟网络/时钟检查状态机的重复投递、取消、超时和音频忙碌；避免为板级驱动编写大量替身测试。
  - 实机检查录音参数、multipart 上传、内存有界、提示与原声切换、重连及掉电恢复。
  - 交付固件路径/版本、构建与烧录方法、脱敏配置、逻辑按键映射、串口结果；标明模拟检查与实际板验收。

## 交给 AI / 固件成员的执行指令

> 你负责 Sonar ESP32 的业务接入。读取总计划、架构、contracts.md 和本任务包，保留已有硬件框架，按 E1→E5 实施。只修改 firmware/ 或已明确的固件工程。优先实现接邀请、提示、独立确认的回复上传；硬件缺失时开发适配层及模拟状态机并明确缺口。不能自行改变音频格式、接口字段或取消确认。构建、烧录、设备与联调各自报告证据。
