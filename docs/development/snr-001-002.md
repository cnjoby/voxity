## 统一契约（SNR-001）

服务端验证模型位于 `server/app/contracts.py`，冻结 JSON Schema 位于 [contracts/v1/schemas.json](contracts/v1/schemas.json)，跨端 fixture 位于 [fixtures/contracts-v1.json](fixtures/contracts-v1.json)。Android 在 `Models.kt` 中提供解析和请求构造。

- `VoiceMessageView`：六要素 `time / place / subject / event / body / state`，以及可见性、收件人、真实对话根和父消息。
- `AgentTurnResult`：统一的动作结果；包括查询回应、澄清、问人任务、发布、私聊、真人交流、忽略、暂缓和未知。
- `SessionCapabilities`：六项独立能力，省略为 false，`schema_version="1"`；拒绝字符串布尔值与未知输入权限。

`GET /v1/contracts` 在设备鉴权后返回上述 Schema。`GET /v1/messages/{message_id}` 返回 `{message: VoiceMessageView, server_time}`，复用现有原声访问规则。公开来源不会暴露其他人的位置快照、绑定 ID、私有目的地或回执；participants 交流只有双方可访问，结束后沿用原有失效规则。

投影不改写旧内容：未知观察时间保持 null，不将录制／上传时间当观察时间；事件模型尚未实施时保持空；运营来源与真人音频形式分别表达。旧 `root_question_id` 可投影为真实 question 或 scene 的 `conversation_id`。审核默认 `not_evaluated`，不把旧内容自动标已审核。`state.task` 保留旧任务状态的原含义，answered 不等于需求已解决。

## 创建会话与权限

新旧客户端共用 `POST /v1/exchange/sessions`；新增等价入口 `POST /v1/agent/sessions`。新客户端发送：

```json
{
  "client_request_id": "11111111-1111-4111-8111-111111111111",
  "expected_revision": 1,
  "place_id": "已登记的地点ID",
  "capabilities": {
    "schema_version": "1",
    "private_query": true,
    "request_humans": false,
    "publish_scene": false,
    "reply_thread": false,
    "match_chat": false,
    "auto_play": false
  }
}
```

`place_id` 仍为兼容所需的已登记会话上下文，不作为用户实际位置或未明确目的地的替代。私人天气查询和私聊不要求有效定位；驾车路线仍要求本人的有效原点。会话至少授权一项能力。

| 权限 | 允许动作 | 不隐含的权限 |
| --- | --- | --- |
| private_query | 私人信息查询、私人助手聊天、相关地点澄清 | 向真人公开问题、匹配或分享 |
| request_humans | 将明确现场问题发给合格参与者；目的地消歧 | 自动分享观察、车友闲聊 |
| publish_scene | 授权范围内的本人现场观察 | 向真人发问、回答／追问、找车友 |
| reply_thread | 回应合法邀请／真实线程 | 新建独立现场问题、任意建立回复对象 |
| match_chat | 主人明确要求后建立真人闲聊及双方原声交流 | 在线即同意聊天、直接转 AI 陪聊 |
| auto_play | 异步相关原声的自动播放 | 上传或公开录音 |

用户主动查询的必要澄清／答案可以作为该查询的直接回应；`auto_play` 管理异步原声自动交付。所有播放仍服从本地安静、说话让路和音频占用。

新请求不能同时带 `capabilities` 和旧 `auto_publish / auto_play / network_enabled` 字段，避免两套授权互相覆盖。新会话响应含 `authorization_format="capabilities_v1"` 和最终 capabilities；客户端必须核对，不能在旧服务拒绝后自动退回更宽的旧授权。

新权限写入可空的 `exchange_sessions.capabilities_json`，沿用增量迁移。旧行保持 NULL，按原行为解释：

- `auto_publish` 允许原有现场分享、线程回应及既有私人查询；旧本地现场 question 保留原规则。
- 远程问人／真人闲聊仍要求 `auto_publish && network_enabled`；缺少 network 标志不能获得这些能力。
- `auto_play` 保留原收听范围。旧会话的请求指纹保持兼容；重试、重启不产生新授权。

能力在一次会话内不由模型或工具扩大。更换能力需显式创建新会话；暂停／结束使旧版本在途动作失效。全局 quiet 和个人参与意愿继续约束执行。

## 统一入口（SNR-002）

核心应用方法为 `Service.submit_agent_turn`：

1. 校验身份、请求幂等性、会话版本、时效和当前模式。
2. 优先保留真实对话／邀请上下文；明确工具查询、找车友与私人聊天分别处理。
3. 复用既有地点消歧、地图工具和结构化现场决策；查询许可在外部查询前校验。
4. 在事务外完成推理／查询，结果返回后重查会话、个人版本、上下文、时效和对应动作许可。
5. 只有原始真人录音和合法关系齐备，才创建／发布或参与原声交流；结果落库并生成统一投影。

| 入口 | 输入／行为 |
| --- | --- |
| `POST /v1/exchange/sessions/{sid}/utterances` | 原有 multipart 真人录音入口；内部委托相同应用方法，保留协议和校验 |
| `POST /v1/agent/sessions/{sid}/turns` | JSON 文本轮次，字段同 `ExchangeUtterance`：请求 UUID、会话 revision、transcript、带时区 recorded_at |
| MCP `agent_turn` | 同一文本轮次加 session_id；身份仍由平台绑定解析；调用相同应用方法 |

旧返回字段 `status / action / post_id / root_id / agent_response` 保留，新增 `result: AgentTurnResult`。异步轮次查询同样返回该投影。`get_feed.agent_session` 只提供本人的活跃会话和能力，供 MCP 获取可信会话及版本；无会话时 null。原有只读 `find_places / get_place_weather / get_driving_route` 保持兼容，不增加公开写权限。

文本入口不能提供客户端自称的作者、邀请或原声路径。若文本请求需要新公开发言或真人交流而没有本轮原声，返回 `deferred / ORIGINAL_AUDIO_REQUIRED`，无公共内容／匹配副作用。若已有合法音频提问正等待地点澄清，文本可补全地点并使用原问题录音；仍检查原始权限、版本和录音期限。

未获对应能力的动作返回 `deferred / CAPABILITY_NOT_AUTHORIZED`；旧网络授权不足保留 `NETWORK_NOT_AUTHORIZED`。会话不存在／属于他人、过期或暂停等沿用 404／410；只收听会话提交轮次返回 403。未知字段或新旧授权混用返回 422。

「和 AI 聊聊」直接选择私人助手；普通「想闲聊」沿用真人匹配、无匹配时询问是否接受 Agent 陪聊。工具失败不会自动扩大为公开问人。明确回答／追问上下文不会仅因“多少车位／天气”等关键词变成新地点查询。

## Android 与固件兼容

Android `SessionCapabilities.sessionRequest` 构造新请求，`AgentTurnResult.parse` 兼容新旧结果。`SonarApi.agentTurn` 使用统一文本入口；原声仍走兼容的 multipart 入口。`SonarViewModel.startExchange` 和实际前台服务支持显式 capabilities，可在无公开许可时进行私人语音处理；不升级原有界面同意范围。

新分项会话按 `acceptsInput` 决定采集／识别，按 `needsLocation` 决定位置前台服务与更新，不以 `auto_publish` 判断能否查询。现有界面继续使用其已展示的旧授权组合；完整分项设置界面属于 SNR-005。不支持新协议的服务会明确失败，不自动回退扩大许可。

ESP32 可继续使用旧协议。新固件按 Schema 显式发送需要的能力，读取结果与来源；不得把仅收听视为发布权限，不能用 MCP 文本合成他人的真人原声。固件、板卡声学和真实双端验收不由本轮软件测试代替。
