# Sonar 表达重组：把一个需求交给自己的 Agent

日期：2026-10-25。状态：表达建议，待审阅。依据：[产品定义与功能架构](product-architecture.md)、[语音网络设计](voice-network.md)、[SNR-001/002 实现与分层验证](../development/snr-001-002.md)、[SNR-003/004 实现](../development/snr-003-004.md)及[当日后端发布记录](../../deploy/deployment-snr-003-004-20261025.md)。这是产品表达与视觉方案，不变更功能或授权范围。

## 表达的中心

**对外主张：说出你关心的事。声呐替你找消息，也帮你问现场的人。**

**产品类别：由车主与各自个人 Agent 构成的语音网络。**

品牌句继续使用“听见同路的声音”。这里的“同路”表达品牌情感，不能据此承诺已完成路线、方向或同目的地匹配。

完整介绍：声呐以车内免提语音为入口。你说出当前位置、沿途或目的地的需要，自己的 Agent 查找仍适用的信息，必要时按授权联系在场且愿意回应的人。对方的 Agent 管理对方的邀请与意愿，真人回答以原声回来。你的 Agent 继续等回复、接续追问，并安排合适的收听时机。

这轮表达面向前文的黑客松评委与初次接触产品的车主，首先要让他们理解“一次需要如何得到合适回应”。面向评委时再补充商业路径与工程证据。页面不要求用户先理解后台服务、字段或 MCP。

## 从最新文档得到的表达调整

| 旧稿重心 | 最新基线要求 | 新表达 |
| --- | --- | --- |
| 就近找人，收发原声 | 提问者可以远程查询目的地，现场资格约束回答者 | “还没到，也能问到现场”作为首个故事，明确目标地点与本人位置不同 |
| 人、广场、个人助手 | 人与自己的 Agent、另一位车主与其 Agent 共同协作 | 主图呈现两个人和各自的助手，网络服务退到承载角色 |
| 有需求便发邀请 | 按需求选择有效公告、已有观察、工具或真人来源 | “先找适用消息，需要时再按授权问人”；明确要求问人时直接建立对应任务 |
| 播放一条原声即完成 | 收到、听完、用户认为解决分别记录 | “有一条回复，可以追问或结束”，不自动显示“已解决” |
| 三类公共声音 | 四条业务线及统一私人入口 | 问现场、听地点、看场所公告、找车友分别表达，私人助手对话保持私有 |

核心需要可以这样说：**你关心的地方可能还没到，知道情况的人也未必在你的联系人里。问完以后，还需要有人替你把回应接回来。**

## 用一个停车需求讲清产品

以下全部为设计示例，不是真实停车场状态或用户访谈记录。

车主 A：“帮我看看世纪公园西门停车场现在还有位吗？”

1. **问清目标。** 知道明确 POI 才继续；缺少景区名称或有同名地点时，只补问必要信息，不用会话预选地点冒充目的地。
2. **查适用信息。** 检查当前公告、有效观察或相关回答。停车规则和区县天气都不能当作实时车位。适用信息带着来源与时间回来。
3. **需要问人时守住授权。** 仅私人查询许可下，缺少答案先问一次是否联系现场车友。用户明确说“帮我问问那边的人”，则在相应授权内直接建立任务，不反复确认。
4. **两个助手协调，真人自愿回答。** A 的 Agent 交出明确请求，B 的 Agent 根据现场资格和 B 的意愿决定是否邀请。B 自愿说：“我在西门，刚看到还有几个位。”
5. **接回原声，继续处理需求。** A 在允许的空隙听到 B 的原声，可追问“从哪个入口进”，也可结束。离开起点不丢失等待；没有回应保留真实等待或超时。

对外避免将这套目标流程说成已全部打通：明确地点及已有内容的合法检索、个人任务台账已随 SNR-003/004 后端发布；完整设备、真实语音供应商与真人验证仍另行进行。当前规则检索不承诺任意语义搜索或事实真伪判断。

## 四种需要，用四句人话介绍

| 用户会说什么 | 页面如何解释 | 需要说清的边界 |
| --- | --- | --- |
| “帮我问问那边还有没有车位。” | 问现场的人，听有来源的原声 | 本人可以远程问，对方需要满足现场条件并愿意回应 |
| “听听这里的故事。” | 到了一个地点，发现别人留下的声音 | 录制时间可见，过去的感慨不当作当前事实 |
| “这里哪个入口能进？” | 查有效的场所公告，也可以继续问 | 运营主体与适用范围明确，旧公告到期或被更新后失效 |
| “找个也想聊两句的车友。” | 双方愿意，再开始原声交流 | 互助不等于同意闲聊；未匹配时先征询是否接受 AI 陪聊 |

“和 AI 聊聊”直接进入私人助手。“我想聊聊天”先按真人交流意愿匹配，未匹配时只问一次是否接受 Agent 陪聊。两种需要不混用，也不把私人对话发到公共空间。

## AI 的表达

主讲只解释三件事：

- **理解与选来源。** 大语言模型帮助听懂地点、时间、事件与意图，整理已有信息，辅助匹配。
- **决定下一步。** 独立的决策任务分别处理发布意图、内容审核、邀请提醒与收听相关性，各自选择允许的动作。不能拿“适合提醒”当作“已经审核”或“用户允许公开”。
- **持续等回应。** 个人任务记住你在等什么，收到、听完与解决分别记录，取消以后迟到的结果也不能重新启动任务。

权限、来源、可见范围、有效期与真实问答关系，由固定规则裁决。模型不能扩大授权或编造现场事实。工具回答用助手身份，真人回复用本人原声。

页面显示来源与声音形式时使用两个独立维度：“谁提供信息”“谁在发声”。授权运营方也可能发布真人录音；不能把“运营公告”和“真人原声”当成互斥标签。

## 商业价值的讲法

`[ASSUMPTION]` 商业起点仍建议为一个授权 POI 与少量自愿参与车主。运营方维护基础公告，车主补充现场观察，先让单个地点有可用的信息与回应。

车主的价值：减少到处找消息的操作，在需要时得到适用信息，问完不用持续盯着等。运营方的价值假设：更方便地发布、更新和撤回告知，让有需要的到访者获得信息，观察重复问询能否减少。认证核验来源与管理权限，动态信息仍需维护。

付费验证：运营方是否接受试点服务费或订阅，实际使用后是否续用，交付与维护成本是否可承受。主机厂接入收费取决于单独确认的采购范围。品牌服务、拼车和用车撮合属于后续独立商业验证，保持在增长路径或附录。

团队有 xAtom、灵矽与主机厂底座合作意向，是用户已确认的资源；声呐试点、预装、车主渠道与收入尚无已落实证据。

## 视觉表达方向

建议方向为“沿途的回应”。面向评委的一张页面，核心任务是让人看见一个需要怎样出发、经由两个个人助手、带着来源回来。车内免提是入口，画面的中心是需求和回应。

### 颜色与字体

| Token | 色值 | 语义 |
| --- | --- | --- |
| 路牌蓝 | `#284BC1` | 私人需求、自己的 Agent、请求线路 |
| 雾银 | `#EEF2F6` | 主要画布，提供清楚的留白 |
| 石墨 | `#202C3B` | 正文与关键标签 |
| 现场珊瑚 | `#D85C43` | 真人原声与回程线路 |
| 信息浅蓝 | `#BFD8EC` | 合法信息与辅助底色 |

标题中的 Sonar 使用 Avenir Next Condensed，中文标题与正文使用 Hiragino Sans GB，以粗细和字号区分。时间与状态可用 Menlo。实际生成前核对字体可用性。颜色是阅读辅助，来源和状态同时用文字标明，不单独依赖色彩。

### 构图与签名元素

比较过三种结构：大地图会让人误以为导航产品；通用功能卡片会弱化个人 Agent 的协作关系；最终建议用一条“有回程的声音线路”。它只用于解释真实的协作顺序，其他页保持安静，不重复装饰编号。

```text
“西门还有位吗？”                       车主自愿回答
  你 —— 你的 Agent ——— 对方的 Agent —— 现场车主
          适用消息／按授权问人
  你 <—————— 原声、来源与时间 <———————
                  等待仍属于你
```

上述为逻辑示意，不宣称点对点基础设施、模型自由互聊或每人独立运行服务器。信息查询不强行画成每次都经过另一位真人。

首页或封面可以让“还没到，也能问到现场”占据主要空间，一条需求线路横跨画面，把问话和有来源的回应放在两个真实端点。这个比例选择是本轮主要视觉风险，其余内容不叠加雷达、装饰波形或发光粒子。

若做网页，只有用户主动启动“看一个例子”后才推进线路，支持键盘、暂停与减少动态效果。若做 PPT，用静态的请求与回程线路，确保无需动画也读得懂。所有界面示意标明“目标体验／设计示例”，不当作设备截图。

## 界面用语建议

以下为表达候选，须结合对应能力实际验收后采用。

| 状态或动作 | 建议文字 |
| --- | --- |
| 发起需求 | “你想知道什么？” |
| 目标不清楚 | “你说的是哪个景区？” |
| 只有私人查询许可且暂无有效信息 | “还没有找到有效停车信息。要问问现场车友吗？” |
| 等待原声 | “在等世纪公园西门的回复” |
| 收到回答 | “有一条回复” |
| 继续需求 | “继续追问”／“结束这个问题” |
| 观察时间未知 | “观察时间不详” |
| 无人回应并到期 | “暂时没人回应。可以重新问，或结束这个问题。” |
| 发送结果未知 | “还没确认是否发出，正在核对” |
| 安静 | “暂停自动出声” |
| 关麦 | “结束本次采集” |

“结束这个问题”表示用户结束等待，不自动作为“问题已解决”的反馈。“已解决”需要明确反馈或预先定义的完成条件。
