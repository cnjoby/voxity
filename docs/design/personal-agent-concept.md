# 声呐 Sonar｜产品定义

> 听见同路的声音。

**声呐是一个由人发声、个人 Agent 辅助参与的城市声音社区。人负责提问与回答，广场组织声音，Agent 帮主人筛选、收听和追踪任务。**

## 三方分工

| 角色 | 职责 |
| --- | --- |
| 人 | 主动提问、分享观察、自愿回答，决定是否公开和参与 |
| 广场 | 存储真人原声与转写，补全地点、时间、主题、来源与问答关系，提供有效候选 |
| 个人 Agent | 根据主人的行程、关注与交流意愿筛选候选，安排提示和播放，追踪尚未结束的问题 |

广场按权限、地点、方向、时效筛选；个人 Agent 按“我关心什么、愿不愿意帮忙、现在能不能打扰”决定下一步。公共元信息可以补全结构，不能补造现场事实。

每个人的配置与任务独立保存，程序和服务器可以共用。个人 Agent 的价值是替主人管理注意力、等待回复，而问答的内容与参与决定来自人。

## 核心场景

- **现场互助**：A 问“现在中环路金科路口堵不堵？”B 恰在现场且愿意互助，B 的 Agent 提示有人询问；B 自愿回答，A 的 Agent 收到回复后安排原声播放。
- **同路通勤**：起终区域、方向和时段相近的人交流，Agent 根据本人的兴趣与意愿选择声音。
- **同一目的地**：去同一景区的人分享停车、入口和沿途体验，Agent 关注与主人行程相关的消息。

人可以拒绝、暂不回应或保持安静。私人助手对话默认不公开；发到广场的声音经本人确认。现场答案保留真人原声、时间与来源；无人回复就说明当前状态。

## 两天原型

只验证一个预设路口、两位用户的“提问→个人筛选→主动提示→真人回答→原声回传”，再用静音或关闭互助展示个人意愿确实生效。位置与方向明确标注为模拟。

ESP32 与 Android 为语音终端；Linx 提供语音交互与工具调用；单台 Sonar 服务器保存广场、每人的配置与任务。新问题事件触发个人规则，在线客户端轮询并播放固定询问提示；不需要为每个人运行独立的常驻推理进程。

同路闲聊和同目的地交流保留为产品方向，核心闭环通过后再扩展演示。
