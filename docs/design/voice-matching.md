# 声呐｜声音匹配与交付需求

日期：2026-10-24。状态：服务端及 Android 前台扩展已实现，本地验证见[实现与验收](../development/voice-matching.md)；物理到达及真人体验待验收，私聊与实时对讲尚未开放。

## 产品目标与来源

让一段声音在合适的关系、情境或地点中被需要它的人听见，同时让人知道“为什么收到、谁说的、什么时候有效”。发声者负责内容和发布确认，广场负责权限、元信息与候选，个人 Agent 管理本人的收听和注意力。

用户在 2026-10-24 提出三类需求，作为本次产品范围：

| 类型 | 用户给出的场景 | 匹配依据 | 收听者期待 |
| --- | --- | --- | --- |
| 上下文问答关联 | 一个人讲话回答另一个，类似对讲机，有明确对象 | 问题、回复链、接收对象与访问权限 | 回答回到正确的人，连续交流不串话 |
| 情境匹配 | 开到优美风景处，听到别人此前在此的感慨或解说 | 声音指向的地点、适用情境、有效期与个人兴趣 | 到了这里，听到与此刻有关的声音 |
| POI 公共频道 | 景区、商场或停车场运营人员发布“B2 满了，请去 B3” | 运营主体、所管理 POI、适用范围与当前有效版本 | 到达的人都能获得与此地相关的有效告知 |

三类允许重叠：停车公告可引发一条定向追问，景点解说可来自运营频道。关系、内容用途、来源和触发方式分别记录，不把一段声音强制塞进一个互斥分类。

**设计假设，待体验验证：**“都会收到”指进入适用范围的可服务用户均可获得公告，不按个人兴趣漏掉基础运营告知；出声仍由用户的收听设置决定。当前客户端只在前台会话中服务，不能据此承诺锁屏、离线或退出应用后的到达推送。

## 三条用户流程

### 1. 有对象的问答与连续回复

A 发出现场问题；B 的 Agent 判断其是否适合回应，B 自愿回复。A 收到与该问题绑定的原声，并可针对 B 的回答继续追问。界面保留问题、当前回复对象和上下文；开始录音前能确认“回复谁、回复哪一句”。

FR-01：每次回答必须绑定确定的原问题与被回复内容；首轮回答直接绑定问题即可。多轮交流需另保存明确接收对象。不能仅凭同地、同主题或文本相似把两条声音认作问答。

FR-02：当前原型保持“确认后公开”的问答模式。“回复给 A”表示交付对象明确，不自动变成仅 A 可见。后续若提供私聊，必须在发布前明确可见范围，校验每一轮权限；公共追问不能把原本私密的内容自动公开。

FR-03：已建立的问答关系在用户离开提问地点后仍可交付有效回复。邀请现场回答时检查现场资格，回答交付时检查对话权限和任务状态；不能让提问者移动后收不到自己等待的答案。过期或已取消的问题不被迟到回复重新激活。

“类似对讲机”在这里指有对象、可连续的异步原声交流。即时通话、持续占用麦克风、多人抢麦不在本次需求内；多轮定向回复也是新增能力，不能用现有单轮闭环宣称完成。

### 2. 到了此处，听见情境声音

B 在观景点录下“从这里看落日特别漂亮”，确认关联观景点并公开。A 后来进入该观景区域，开启情境收听时，Agent 根据地点、适用时间、兴趣和已听记录选择是否提示。A 可听原声、稍后听、跳过或减少此类推荐。

FR-04：作者确认声音的目标地点和用途。声音可表达感慨、体验、解说或现场观察；录音位置、内容所指地点和收听者当前位置分别保存。作者恰在附近或提到地点，均不足以证明该声音适用于该地。

FR-05：长期知识与即时观察分别处理。“这座桥的来历”可长期保留，但仍需来源与更新时间；“这里现在能看到落日”“入口正在排队”要有适用条件或短有效期。历史感慨注明录制时间，不作为当前天气、景观或客流的证据。条件未知时可供主动浏览，不做“现在正适合”的主动推荐。

FR-06：到达不等于自动播放全部声音。符合硬条件后，情境内容按本人的收听开关和关注选择；同一访问内限制提示次数，已听内容默认不重复。具体提示间隔与条数作为待验证配置，不在本次设计中虚构已验证阈值。

FR-07：用户可主动说“听听这里的故事”获取合法候选。主动查询允许查看远处地点；仅因手选或查询目标，不产生“已到达”的自动触发。

### 3. 进入 POI，获得公共信息

停车场授权运营人员发布：“当前 B2 已满，请前往 B3。”发布时指定停车场、入口或楼层范围、开始时间、失效时间。A 到达该停车场入口后，在该 POI 信息中获得当前公告；允许播报时听到一次短告知。运营人员更新为“B2 已恢复”后，旧公告从待播队列撤下。

FR-08：频道绑定一个明确的 POI 与管理范围。仅被授权的主体可以该 POI 运营身份发布、更新、撤回；普通用户的观察保留个人来源，不显示为运营告知。频道名称或自称运营不能授予权限。

FR-09：同一频道中区分公共知识与即时公告。知识包括停车规则、营业入口、设施说明，供主动询问或按需解说；即时公告包括车位满额、临时封闭和入口调整，按当前有效状态交付。不能把频道内所有知识在到达时逐条广播。

用户也可在 POI 频道提问，由运营人员或其他参与者自愿回答，沿用明确的问答关系与可见范围；运营回复与访客回答分别标明来源。一条回复不会自动变成面向所有到访者的运营公告，运营方须另行确认发布范围和有效期。

FR-10：每条即时公告必须指定生效与失效时间，并支持撤回、被新版本替代及到期自动失效。动态车位信息未更新且已过期时，显示“暂无有效停车公告”，不继续播报旧状态，不自动推断 B3 一定有车位。播放时注明“停车场运营方于某时发布”。

FR-11：有效公告对适用范围内的可服务用户可见，无需先关注或开启“愿意回答问题”；兴趣筛选不能隐藏基础运营告知。自动出声仍服从静音、频道收听偏好和音频空闲状态。用户可主动查询；送达、看到、听完分别记录，不把服务器生成交付当作人人听见。

FR-12：公告范围可以是整个 POI、入口、楼层或区域。首版若只能确认停车场附近，提示该范围，不声称已进入 B2。无法可靠区分楼层时不触发仅适用于某层的自动播报，可提供整个停车场公告供主动查询；不以二维 GPS 半径冒充楼层定位。

FR-13：同一公告版本在同一次有效访问中默认只主动提示一次；短暂定位抖动不算新访问。原公告发生实质更新且仍适用于本人时可再次提示。公告撤回、替代、到期或用户离开范围后，未开始的到达播报失效；实际播放前重查有效版本。访问离开判定与冷却窗口待位置测试确定。

## 共用交付规则

“等待回复”“订阅地点或主题”“仅本次到达收听”是可跨三类使用的关注方式，不额外新增第四种声音。等待回复已有任务基础；订阅和到达收听为后续产品能力，订阅远处地点也不能赋予现场回答资格。

FR-14：先按内容权限、任务或频道关系、适用空间、有效期和用户授权决定能否交付，再按收听偏好决定是否出声。互助开关只控制回答邀请；情境收听、运营频道收听和等待自己的回复各自有设置，不能共用一个开关误关其他能力。个人静音统一阻止自动出声。

FR-15：同一声音因多个入口命中时合并交付理由，不重复播放。用户能看到“回复了你的问题”“你到达了此观景点”“该停车场的有效运营公告”等实际原因，并能停止播放、稍后听、跳过、减少情境推荐或关闭频道自动播报。

FR-16：所有声音显示原作者或运营主体、录制或发布时间、适用地点及必要的有效期。运营身份只证明来源和授权范围，不保证现场状态永远准确；个人观察与运营公告冲突时保留双方来源和时间，不静默拼成新事实。Agent 不编造答案，也不以系统合成声冒充真人原声。

FR-17：录音、已有播放和系统提示串行；录音中到达的提示延后。默认先处理用户主动发起的当前收听，再排队自己的问题回复、有效运营公告、回答邀请、情境推荐；不抢断当前录音或播放。过期、撤回、静音和权限变化在出声前重查。此顺序是待体验验证的初始设计，无强制越过静音的公告等级。

FR-18：延后内容不能无限积压。情境推荐离开适用范围后撤下；到达公告按当前有效版本查询；自己的问题回复保留待听且受任务和访问权限约束。联网恢复后重新核对有效内容，不把离线缓存的动态公告当作最新状态自动播放。

发布者不获得收听者精确位置或完整到访名单。匹配使用必要位置上下文，对外展示地点和适用范围；跨用户的任务、播放回执与配置分别保存。客户端不具备后台唤醒时，产品只承诺会话有效期内的可达性。

## 体验验收

以下为产品目标用例。服务端规则与 Android 前台交互验证分别记录于[实现与验收](../development/voice-matching.md)；实体设备结果尚未取得，不能据本地测试宣称全部体验验收。

| 编号 | 给定 / 操作 | 应得到的结果 |
| --- | --- | --- |
| AC-01 | A、C 在同一地点各提一问，B 明确回复 A | 仅关联 A 的原问题及指定接收对象，不因邻近把回复放进 C 的任务 |
| AC-02 | A 发问后离开，B 在有效邀请内回复 | A 仍能取得自己的有效回复；静音时保留待听，取消后不迟到出声 |
| AC-03 | 在公开问题中继续追问，或试图转发私密内容 | 显示明确回复对象及可见范围；未经授权不能公开私密原声 |
| AC-04 | A 到达观景点，存在历史感慨和已过期的实时观察 | 可推荐注明日期的历史感慨，不播成当前事实；过期观察不主动推荐 |
| AC-05 | A 远程搜索观景点，或未开启情境收听 | 可以主动浏览；搜索不冒充到达，未授权时不自动播放情境声音 |
| AC-06 | A、B 到达有公告的停车场，二人兴趣不同，B 静音 | 二人均可取得有效公告；A 按设置听到一次，B 不出声且能主动查看 |
| AC-07 | B2 满额公告已排队，此时被更新、撤回或到期 | 旧版本不开始播放；更新后按适用范围提供当前版本；无有效版本明确告知 |
| AC-08 | 用户短暂定位漂移，或处在楼层未知的停车场附近 | 同一访问不反复提示；不把“附近”说成“已进入 B2” |
| AC-09 | 普通用户冒充运营，或运营账号跨 POI 发布 | 不能取得该 POI 的运营身份及发布权限 |
| AC-10 | 同一声音同时命中订阅、地点和回复关系 | 一次交付、理由可见，回执重试不重复播放 |
| AC-11 | 录音中出现公告；随后静音、离开或断网重连 | 录音不被打断，恢复后按当前设置及有效版本决定是否播放 |
| AC-12 | 同一频道包含十条知识说明和一条当前停车公告 | 到达时只提供适用告知；知识按需获取，不连续广播整本指南 |

后续试点观察：回复关联错误、过期公告出声、重复提醒、静音违规都应为零；分别记录合格会话的公告可达率、用户主动收听率与跳过/关闭比例。分母应包含符合范围的有效会话，不能用生成任务数代替实际收到数。没有实测数据时不填写覆盖率或提升结论。

## 交付边界与待决策

最初文档只完善产品需求；随后按用户“继续完成实现”扩展了兼容接口、增量数据库及 Android 前台。两天现场问答的设备完成标准保留；完整产品范围的试点体验仍须另验收。

建议后续最小验证：一个观景点的已确认原声、一处停车场的授权运营账号与一条可更新公告，先用前台会话验证进入、静音、去重、替代和过期。演示注入坐标只能证明规则与交互，物理到达、楼层识别及驾驶期间体验需另验收。

| 待定事项 | 负责角色 / 决定时机 |
| --- | --- |
| 是否将情境声音或运营频道纳入下一次演示，以及两者顺序 | 产品负责人，在开发排期前确定；不自动加入当前必交付 |
| POI 运营资格如何核验与撤销 | 产品与运营，在首个试点频道开放前确定；封闭演示可人工授权并标记演示身份 |
| 各种动态告知的有效期、访问冷却和提示频率 | 产品与研发，在具体 POI 试点前配置并实测；缺省有效期不得产生长期有效的动态公告 |
| 多轮定向交流是否需要私聊及权限模式 | 产品负责人，在多轮功能开发前确定；此前保持已确认的公开问答 |
| 室内区域/楼层到达证据与后台可达性 | 研发与设备负责人，承诺精确到达或后台服务前验证 |
