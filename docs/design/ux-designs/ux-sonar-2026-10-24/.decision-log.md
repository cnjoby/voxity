# 声呐车用免提交互决策记录

日期：2026-10-24。状态：首版文档已交付，待功能实现、设备和用户体验验收。当前任务只交付规范和开发文档，不修改 App 或固件实现。

## 已确认来源与范围

- 用户明确要求：手机 App 与 ESP32 都是放在车内使用的免提客户端，必须遵循同一车用免提交互约束。
- 用户明确选择：两种设备都用各自扬声器；不以蓝牙音响或车机集成为本版依赖。
- 前序用户要求仍有效：交付可以直接发给 ESP32 开发同学的独立文档，包含全部必要接口与 AI 提示词，不依赖其他本地文档。
- 本版为消费者产品交互约束设计；没有车辆运行信号、驾驶员身份识别或道路实测证据。不能宣称车规、道路安全或法规认证。
- 沿用 Sonar 的广场/个人状态、Linx 语音、Sonar HTTPS 双通道、云端 MCP 分工。用户原声必须由本人独立确认才公开；新要求改变确认媒介，不取消确认。
- 现有 Android Compose 视觉约定：标题 #123E51、主操作 #007F86、背景 #F0F5F5、正文 #163440、边线 #D8E8E9、提醒 #966019、白卡；沿用，不设计新配色。
- 现有 Android 依赖点按、屏幕转写核对，尚无车用本地唤醒/关键指令/后台麦克风实测。ESP32 源码尚未交接。历史 Linx 手机通过证据不能替代本次免提验收。

## 行为决策

1. 形成两个设备共用的逻辑事件、语音词汇、状态和回执；手机屏幕/ESP32 LED 只是状态镜像，主流程零触屏零必需按键。
2. 首次授权、配网、绑定、音量、麦克风与播音测试、进入/结束本次免提会话在停车时完成。无可信车辆状态时不自动判断已停车；免提会话默认保守驾驶约束。GPS 低速不是解锁配置的依据。
3. [ASSUMPTION] 默认唤醒词为“你好声呐”，需实际引擎/模型支持。唤醒词可停车时配置；两端保持同一词汇。实际模型不支持时提交替代词，不声称已实现自定义唤醒。
4. 本地唤醒后短音提示收听；VAD 自动结束，最长 8 秒（现有文件协议）。建议结束静默 1.2 秒，3 秒无人说话退出，等待确认 8 秒，最多重问 1 次；这些都是待车内噪声测试的产品参数而非标准。
5. 【初版口令规则，已由下方自然语义更新替代】所有公开录音都读回冻结后的准确 STT 文本和目标/对象，明确“将公开”。仅在读回完整结束后，以新一轮语音中的“确认公开”授权具体草稿；“嗯/好的/播放内容/预先说发出去/超时沉默”不算确认。无需看屏幕或手动核对文字。目标或转写变更使确认失效。
6. 确认有效窗口只绑定一个 confirmation_id 和不可变 turn_id/audio hash/transcript/target/invitation/post_id；具体字段为客户端内部状态，不增加现有 API 字段。取消、打断、驾驶优先事件、断网、过期、重启使窗口失效。确认网络结果不明允许重试同一已确认 post_id，不偷偷新发。
7. 读回使用准确文本的 TTS 通道（Android 系统 TTS、ESP32 文本 TTS 适配需验证），不能用开放助手随意复述，不把 AI 合成的读回当真人原声。若没有可靠读回或 STT 无法归属，则保留私有草稿，停车处理，不能退回行车屏幕核对。
8. [ASSUMPTION] 主动邀请只播一句“附近有人想问路况，要听吗？”，不自动录制/公开。用户“听问题”后播原问，“我来回答”才录音。自己的回复到达只短提示，用户“播放回答”后播原声。一般分享/公告行车默认不主动打断；测试素材只允许停车主动试听。
9. 用户说“停一下”只停止当前出声/捕获，不取消公开问题；“安静”立即抑制所有普通声音、保留待听，仍本地等待唤醒与恢复；“关闭麦克风/结束免提”释放麦克风，此后必须停车手动开启，不谎称还能语音唤醒。
10. [ASSUMPTION] 陌生邀请合并为同一时段最多一次提示，默认间隔 120 秒；逾期不再播报。本人期待的回答单独短提示，不连播、不催答。通知在录音、核对、确认、电话/导航让路、安静期间排队或到期丢弃。
11. 本地高优先级“停一下/安静”必须断网可用，且播放中可识别；麦克风采集可同时服务唤醒/关键字，但业务录音/公开只在显式轮次内。需要 AEC/降噪、播放参考、拾音布局与机型能力验证。只做云端关键词或播音时关麦不能验收为免提。
12. 手机以自己的扬声器出声；电话/音频焦点丢失停止或暂停，恢复不自动继续播音或确认。ESP32 无手机音频焦点，不能承诺能自动感知另一个手机的导航或真实车辆警报；本地安静与短通知仍有效。禁止把任何提示当紧急驾驶警报。
13. 未确认草稿断网不发布；重启不自动出声/确认，保留本地安静；本机麦克风被系统停止则状态降为免提不可用，不能显示可唤醒。
14. 手机和 ESP32 是可替代主终端，本轮每人一台主终端；两台同车同时唤醒去重/跨设备仲裁未实现，不声称已支持。停车时只启用其中一台会话。
15. 真实位置未知不冒充在场。目标最多一次语音澄清，仍不明则保留草稿；不在行车中读 POI 长列表。模拟位置与音频始终可听见/看见标识，不能以听起来真实替代来源。

## 2026-10-24 自然语义更新（覆盖初版固定确认词）

用户要求更流畅自然，并询问是否可由决策模型处理确认。改为上下文中的自然同意，不要求固定“确认公开”。明确读回公开对象和准确内容后，用户在新窗口说“发吧/就这样发/可以”等，由独立 voice_intent 任务判断；“可以/好的”须结合系统刚问的是听问题还是公开发出。含否定/反问/含混/沉默/媒体内容/迟到结果不发布。

保留每份草稿独立确认、内容与轮次绑定、本地停/安静、权限及时效门禁。不把模型选择当用户授权的来源；模型识别真实用户已经表达的同意。复用推理服务适配，不共享 attention 的业务状态、选项、缓存或阈值。当前 voice_intent 和终端可信接入桥仍待实现，未改服务代码。

独立评审仍按用户前次选择跳过；本次做文档一致性、JSON 与静态预览检查，不冒充语义准确率/延迟验收。

## 2026-10-24 用户再次纠正：减少系统介入（覆盖每条确认/提示播放）

用户原意：说“金科路中环路下面堵死了”，Agent即可帮助发布；符合上下文的回复自动播放。明确不要持续的系统控制声音。新默认为本次会话授权后的自动交流：不逐条读回/询问/确认，不逐条提示等待播放口令。读回和自然确认只作为用户选审阅模式或必要范围变化/歧义的支路。

一次会话授权是本版实现建议，发布与收听分开；现有listen/assist开关不等于自动公开授权。无法区分来源/范围时保持私有，不将全车聊天都发布。安静暂停自动发布和出声，关麦结束会话。用户开口优先于原声播放，系统不解释每一步。

现场陈述无真实问题关系时用scene观察；有有效邀请才answer。同地点相关不创造回复关系。当前reply仅支持已answered问题，scene通用线程待实现。既有产品/接口中的“每条确认”是旧实现约束，新增可信会话授权和执行策略尚未改代码。
