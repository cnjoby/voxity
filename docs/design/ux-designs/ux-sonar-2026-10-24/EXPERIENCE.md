# 声呐｜安静的车用交流代理

## Foundation

**用户正常说现场情况，Agent 在已授权的交流会话中判断并发布；相关回复到来，在合适的空隙直接播放真人原声。系统平时不说控制话术。** 手机和 ESP32 均用自身扬声器，每人一次只启用一个主终端。

用户已明确纠正前版：不再以“每条读回、询问、确认”和“先提示、等播放指令”为默认路径。原每条确认方案仅保留为用户选择的审阅模式或少量必要澄清。本文件覆盖前版对应规则，现有 App/固件实现状态不因此改变。

停车准备时一次开启本次“现场交流”：明确允许自动发布哪些现场内容、公开到哪里，以及是否自动收听相关回复。发布和收听分别授权，随时暂停/结束。默认不把私人助手或车内闲聊视为已授权公共内容。会话授权由独立 exchange session 保存，发布和播放分别授权；不能仅凭 assist_enabled=true 或 mode=listen 推定已经授权自动发布。

[DESIGN.md](DESIGN.md)规定视觉镜像。手机屏幕/ESP32 指示不承担必需确认；同一会话内不反复要求唤醒、说“我想提问”、听控制提示或念口令。首次授权、配网、权限、模型/拾音自检在停车完成。无可靠车况时不从 GPS 低速推断已停车。

2026-10-25 已提供 Android 有界语音采集、自然发言提交、独立会话授权、相关原声调度及服务端复核实现，详见[实现与验收边界](../../../development/natural-exchange.md)。ESP32 固件、真人完整语音闭环和车内声学仍待实现/实测；本轮软件测试不等于道路安全认证。

## Information Architecture

| 表面 | 作用 | 是否主动出声 |
| --- | --- | --- |
| 停车准备 | 开启本次现场交流，确定发布范围、收听设置、主终端、拾音与隐私 | 仅按用户操作做必要自检 |
| 自然交流会话 | 有界捕获面向交流的语音，分类、发布、安排原声播放 | 正常成功无控制播报 |
| 当前上下文 | 保存本人正在说的内容、等谁的回复、地点/任务/会话关系 | 屏幕/指示只镜像状态 |
| 待听/延后 | 录音、电话、安静、相关性不足时保留有效内容 | 等允许时机；不逐条提醒 |
| 停车收尾 | 私有暂存、发送结果、错误、撤回与配置 | 停车主动查看或用户主动询问 |

手机驾驶页只镜像“交流中”“已分享”“相关回复播放中”“已安静”等真实状态，使用 {typography.status} 和 {components.current-turn.radius}；没有必须阅读的转写卡或确认卡。[静态预览](mockups/handsfree-states.html)只示意状态，不证明功能已实现。

## Voice and Tone

**正常路径没有系统控制声音。** 不说“请说问题”“说确认公开”“收到一条回答，要听吗”“正在识别”“已发布成功”。用户可主动问“刚才发出去了吗/现在等谁”，再简短回答实际状态。可选低干扰短音默认不重复，不模拟交通警报。

| 情况 | 处理 |
| --- | --- |
| 用户：“金科路中环路下面堵死了。” | 已授权且判断为现场分享时，保存并发布这条真人原声；系统静默 |
| 有人针对当前任务回复 | 满足播放条件时直接播该人的原声；必要来源/时间可通过极短前缀或原声元信息表达，不加流程指挥 |
| 用户：“我再说一句，下面已经开始动了。” | 用当前有效上下文理解；原声保留实际说法，不能悄悄改写成系统结论 |
| 关键地点/对象有歧义，且用户明显在等待处理 | 最多一句：“你说的是金科路中环路口吗？” |
| 普通内容不确定、闲聊或模糊感叹 | 静默忽略或私有暂存，不反复问是否发布 |
| 用户：“安静。” | 本地停声，不再播报“已安静” |
| 用户：“刚才那句别发。” | 未提交则终止；已提交则按真实结果撤回或说明，不能谎称网络事务已被取消 |

## Component Patterns

| 组件 | 行为 | 恢复 |
| --- | --- | --- |
| session-status | 镜像本次授权、采集/唤醒真实可用性；不以联网代表就绪 | 权限/服务失效即不可用 |
| current-turn | 绑定一句真人原声及本轮上下文，显示已分享/暂存/结果未知 | 迟到结果不能改下一轮 |
| waiting-summary | 保存期待回答与有效待听，不以“已回答”当“已播放” | 恢复后重新复核，不连播未知进度 |
| quiet-control | 安静先本地停声/清队列，再同步 quiet | 明确恢复后按当前上下文调度，不补播旧杂讯 |
| setup-row | 停车授权、模式、位置、隐私、范围、历史和撤回 | 不在行车失败时要求解锁或编辑 |
| device-indicator | 真实交流/采集/播放/安静/关麦状态，无必需按键 | 指示不代替语义或授权 |

## State Patterns

授权状态、语音轮次和播音分别保存，不能将“允许收听”当“允许公开”。

| 状态 | 行为 | 禁止 |
| --- | --- | --- |
| OFF / UNAVAILABLE | 无会话或拾音不可用 | 伪装正在听；后台擅自重新开麦 |
| SESSION_READY | 已授权的交流会话，等待真实发言 | 周期提示、每句唤醒、上传全车连续对话 |
| CAPTURING | VAD 有界收束本次发言，保留必要前导音频 | 丢首字、把系统/媒体原声再录成用户公开内容 |
| DECIDING | 用会话授权、用户本轮语音、地点与活跃任务判断 share/answer/question/reply/private/ignore/defer | 按每一句都硬分到“必须发布” |
| AUTO_PUBLISHING | 对合法授权动作创建草稿并提交同一内容 | 模型改写真人原声；过期结果套给新轮次 |
| PRIVATE_DEFERRED | 不确定或无授权则暂存/忽略，默认静默 | 不停追问；断网后无期限补发旧观察 |
| CLARIFYING | 仅关键歧义且用户正在等处理时简短澄清 | 每条读回确认；没有回应就默认同意新范围 |
| WAITING_REPLY | 跟踪已建立任务/会话，系统不播等待状态 | 反复提醒“你还没听/没人答” |
| AUTO_PLAYING | 有效相关回复在可播放空隙直接出声 | 启播前再等一句“播放回答”；与人声/电话重叠 |
| QUIET / MIC_OFF | 安静抑制普通出声；关麦结束会话 | 将静音当关麦，或关麦后假称可语音恢复 |

[ASSUMPTION] 本轮初值：VAD 尾部静默约1.2秒、单文件最长8秒；主动人声开始立即让路，语义链路候选收束至首个动作目标P95≤1.5秒。均须实测；现有8秒是文件协议限制，不可把更长自然发言截断后擅自公开，应暂存并另行设计分段。

## Interaction Primitives

### 一次授权下的自动发布

系统维护本人的会话授权快照：启用状态、允许内容类型、公开范围、地点/话题限制、有效会话、策略版本及撤销状态。字段是待实现设计，不是已有 HTTP 请求字段。跨重启/长时间断线/授权范围变更后暂停待提交动作，不自动续发。

一次发言的通道为：有界采集/STT → 判断是否属于已授权现场交流 → 确定类型和真实关联 → 草稿/发布规则校验 → 幂等提交。符合授权、语义清楚的现场原声正常静默发布，不读回、不逐条确认。无授权或超范围内容不发；用户主动要求审阅时才走单条读回/自然确认。

“金科路中环路下面堵死了”是用户的现场陈述。若它正在回答唯一有效邀请，可以是 answer；否则是 scene/observation，不能凭地点相关就造 reply_to。表达中有地点不自动证明作者在现场，不补造车道/匝道/精确坐标或运营身份。原声必须保留口语和来源，转写不得升级为已核实路况预测。

### 相关回复自动播放

直接回复本人任务/有效会话的原声优先，且不再做多余兴趣筛选；播放时机由本人模式、音频占用、已感知的电话/音频焦点、内容有效性、权限、版本和已听状态共同约束。附加的同地点声音只作为候选补充，不因模型说“相关”就变成针对本人的回复。

当前用户未说话、设备未录音、无更高优先级事件、已授权自动收听、未静音且复核通过时直接播放。用户开口/说停/说安静立刻让路；中断原因决定保留待听还是 skipped，完整排空才 played。网络重试、重启或未知完成状态不触发自动重播。被用户“稍后听”延后的项不能在下一次轮询自行开播。

自动是按合适时机衔接，不是立即把所有候选连播。多个回复按当前任务整理，有界串行；上下文已切换时保留待听。普通公告/陌生分享默认不抢占当前交流。

### 停止、否定和隐私

本地“停一下/安静/关闭麦克风”高于云端判断，播放中、断网时均可用。安静保留本地控制，但暂停自动发布和普通播放，撤销在途尚未提交动作；恢复需明确意图并同步状态。关闭麦克风结束会话，停车手动重开。

媒体/系统自播音不得变成新公共发言。没有可靠驾驶员身份或声源区分时不宣称已支持；会话内仍要识别私人对话/乘客/广播等排除内容，无法确定时静默不发。语义模型高分本身不能绕过来源或授权校验。

## Accessibility Floor

- 主流程零触屏、零必需按键、无需背口令，也无需听一串系统指挥；屏幕可熄灭。
- 状态镜像和TalkBack真实一致，停车触控目标至少48dp；不只依赖颜色或闪灯。
- 手机和ESP32分别用自己的扬声器；音量停车校准，不因噪声无限增大。
- 系统安静不意味着用户听不见真人回复；普通成功无需说“成功”。
- 关键错误只在需要用户行动且不静音时简短反馈；其他留待停车查看。

## Key Flows

### F1｜小林停车时开启这次现场交流

1. 选手机或ESP32为本次主终端，确认麦克风、停止能力及网络状态。
2. 开启“自动分享现场信息”和“自动收听相关回复”，选择公开范围；两项分别授权。
3. **关键结果：进入会话后，后续正常现场交流不再逐条确认。**

失败：没有可用拾音/来源隔离或停止能力，不能显示自动交流就绪；设置保持停车处理。

### F2｜小林自然报告路况

1. 小林说：“金科路中环路下面堵死了。”
2. Agent得到本轮原声与唯一STT，判断为已授权的现场观察。
3. 没有明确回复关系则创建scene观察；有唯一合法邀请才绑定answer，仍校验时效。
4. **关键结果：合法现场原声静默发布，不出现系统读回或“发出去吗”。**

失败：地点/来源/授权不明则私有暂存或忽略；不将一句模糊感叹广播出去。

### F3｜小周的相关回应直接被听见

1. 已建立问题/会话关系的人提供回应；系统收到其真人原声。
2. 确认属于小林正在参与的上下文，自动收听已开启。
3. 小林停止说话且设备空闲，联网复核后直接播放：“我刚过那儿，右边已经能走了。”
4. **关键结果：没有“收到回复，要听吗”的系统插话，真人声音自然接续。**

失败：仅地点相近但无真实回复关系，不伪造为对小林的回答；可作为补充候选另行判断。现有scene通用回复关系未实现时，不伪造运行结果。

### F4｜小林继续交流并控制节奏

1. 小林听到一半开口：“我说的是下面那条辅路。”当前播放先让路。
2. 依据真实当前上下文形成新发言；没有可用关系时不随便给另一个问题。
3. 小林说“安静”，设备停止播音并暂停自动发布。
4. **关键结果：用户靠自己的说话控制交流，系统不抢麦、不解释每一步。**

失败：当前语境已失效则不自动发送，必要时一句澄清；不反复逼问。

### F5｜广播、私人聊天与离线

1. 广播/系统原声含路况句子，或乘客说“别把这段发出去”。
2. 没有合法用户发言与授权动作，不公开；明确否定立即撤销未提交动作。
3. 网络中断或设备重启，保存结果状态而不重放/补发旧观察。
4. **关键结果：自动执行仍有清楚的授权、来源、上下文和时效边界。**

## 实现边界与验收

已存在：question/answer、scene观察、基于已回答问题的reply、草稿/confirm、原声交付和回执。新设计未实现：会话级自动发布授权、连续自然发言来源识别、发布意图/类型判断、安静调度，以及以普通scene为起点的通用回复线程。当前reply要求root_question_id且原问题已answered，不能直接拿scene充当根问题。

不能复用attention的notify/defer/ignore结果、缓存或阈值作为发布授权。可共用模型适配，任务类型、个人上下文和授权状态分别保存。客户端不可凭旧assist_enabled/listen开关自行自动confirm；服务端需新增可信授权及动作验证机制，具体协议另行冻结。

| ID | 测试 | 预期 |
| --- | --- | --- |
| U1 | 两端分别做三轮自然现场发言 | 正常成功无系统控制播报、无逐条确认，保留正确真人原声 |
| U2 | 同句在有效邀请/无邀请/私人助手三个语境 | 分别合法answer、scene、私有/忽略；不串关系 |
| U3 | 合法相关回复在空闲时到达 | 直接原声播放，不等播放口令；已听项不重复 |
| U4 | 用户开口、停、安静、电话/失焦 | 立即让路；安静暂停自动发布与播放；恢复不补播旧项 |
| U5 | 广播、自播音、乘客、模糊感叹、明确否定 | 无未经授权公开；无法区分来源时不发布 |
| U6 | 取消/授权撤销/换语境时模型迟到 | 不执行旧动作；不换新ID偷偷发布 |
| U7 | 上传/confirm/ack丢响应、断网、重启 | 幂等、状态真实，不自动重播或补发过时信息 |

以上是待执行验收，未做车内或道路通过声明。前版文档检查不证明本版自动代理的语义质量、来源隔离或延迟。
