## 产品决定

1. 产品主路径只叫“开始”，没有现场交流/私人查询/问问现场/只收听/聊天的入口选择。默认进入一个个人语音助手会话，用一句话表达目的。
2. 常用启动页：声呐；一个真实就绪状态；主按钮“开始”；一行说明“直接说想知道的事。问人、转告或回应时才把原声发给别人。”；低显著性“连接与隐私”准备入口。首次启动另有一次简短说明和系统权限，不能承诺首次也只有一次点击。
3. 启动说明明确：相关原声可自动播放；可收到少量相关提问，是否回答由本人决定。已有“仅私人/不被邀请/安静”等明确选择继续有效，不能被新界面重置；没有先验拒绝的普通用户以本次“开始”确认可接相关邀请，不另摆互助开关。
4. 开始后零必需触屏。屏幕仅镜像“正在听 / 正在回应 / 等现场回应 / 已安静 / 已结束”，可熄屏。保留安静、结束两个紧急触控兜底及系统通知，不依赖它们完成正常路径。
5. “我的”取消主导航；“我的任务”退出普通产品。内部持久化请求、回应、来源、发送结果、期限与已听状态继续保留。用户说“刚才问的有回应吗 / 再放一遍 / 不用等了 / 继续问他”。不要求说任务 ID、线程或状态词。
6. “现场互助”不做用户开关，拆为可理解的语义：“别人有相关问题时可以问我 / 今天别问我 / 只听不回答 / 有需要再叫我”。无时长“先别问我/这次只听”仅本会话；明确“今天”持续到用户所在时区当日结束，跨会话有效；“以后都……”形成长期偏好。收到邀请最多一个短提示；不回答即跳过，不替人回答，不自动把旁人声音发出。暂停陌生邀请不影响自己的问题收到回答。
7. 模型选择查工具、检索公告/原声、问合适的人、跟踪等待、关联回复、合并摘要和合适播放时机。规则执行身份、授权、地点来源、过期、原声访问、幂等、撤销、音频抢占。停止先本地处理，不等待模型。
8. 私人意图保持私人。“现在还有车位吗”先查已有合法来源。缺少现场答案时可问一句“要我问问在场的人吗？”；“帮我问问现场的人”本身是这次公开提问的明确意图，不再二次询问。不能每次查不到都重复推销问人。
9. “告诉后面车友 / 帮我分享 / 回复他”明确授权当次内容与对象；已授权范围内直接执行，不逐条朗读确认。用户可说“这一路的现场观察都帮我分享”建立本次有界连续分享，之后合格陈述静默执行；日常私人对话不被纳入。模型不能从普通陈述推定用户开了连续公开。
10. “回复他 / 继续问 / 刚才那条”关联最近有效、已实际播出的对话；只有一个合法对象直接执行，多个对象只问一句区别问题，不能朗读编号菜单。等待不阻塞继续和助手交谈；首轮沿用现有一个活跃现场问题上限，切换新问题通过一句“换成问东门车位，之前的不等了？”处理，确认才结束旧问题。

    唯一有效邀请刚实际播出后，在清楚的接话窗口内直接说“东门还有三个位置”即可作为回答；不要求前置“帮我回复”。窗口到期、对象变更或来源不清不公开，必要时短澄清。时长为后续实测参数；不能只因一句话出现在邀请之后就证明它是本人给对方的回答。
11. 原声优先保留。模型摘要和工具结果明确为声呐回应，不伪装成真人。合成测试素材只在明确试听/联调时出声，首条说“下面是合成测试声音”，不作为即时事实；模拟位置和内容合成是两个独立维度。
12. 语音示例是自然表达的样本，不是必须记住的口令。可插话、纠正地点、拒绝、取消、重听、追问、结束。单次澄清只问一个缺失信息，连续两次听不清后说明暂时无法处理，保留原意，不抛给 GUI 菜单。
13. 安静=本地立即停止普通播放、停止业务内容提交与对外发布，只保留本地恢复/结束控制。恢复=明确说“继续/恢复收听”，重新复核当前授权与新鲜度，不补发旧录音、不连播过期消息。结束/关闭麦克风=停止采集并结束会话，下一次只能点击开始或有明确硬件能力的物理启动；不声称关麦后还能听语音唤起。
14. 电话/系统麦克风撤销后暂停，只有麦克风仍真实可用时才允许语音恢复；权限撤销/进程终止回到未开始，停车后处理。不为了无屏承诺常驻后台就一定可用。
15. 失败用语音说明影响和下一步，不宣读错误码。网络恢复先核对原请求，不重复公开；结果未知必须说未知。用户主动等结果时无声音即失败，TTS 故障不能用屏幕文字算成功。
16. 无屏主张的设备门槛：本地停声/结束离线可用、播放时能让人插话且不把回声公开、熄屏继续、听清完整发言、恢复状态可信。当前设备未通过就以“免提暂不可用”留在准备状态，不降级成多步手动菜单。现行音频单片上限 8 秒，长话不能截一半发布；实现分段且保持语义/撤销一致性后再验收长句。
17. 模拟联调入口移到停车准备的“连接与隐私 → 联调位置”，保留三个点位；会话内可说“切到模力社区 / 切到人工智能岛 / 换回手机真实位置”。仅改本人，ESP32 不跟着手机跑。生产模式里“帮我问金科路”仅更改目标，不改本人位置。模拟位置的全语音需要新增明确的联调会话能力，不能直接移除真定位约束。

## 假设与未决项

- [ASSUMPTION] 本轮主要设计 Android 手机与既有 ESP32 的异步原声往返，不承诺实时电话/AEC硬件能力、导航目的地接入或多任务并发已经具备。
- [ASSUMPTION] 使用现有 Compose 海蓝/青色风格；本轮改信息结构和行为，不重新做品牌视觉。
- [ASSUMPTION] 没有明确拒绝偏好的用户，本次开始允许少量相关邀请；先沿用已有 relevance/有效期门禁，冷却建议十分钟一次、不重复相同邀请。冷却数值是试点初值，需要真人验证。
- [ASSUMPTION] 普通轮次无需反复唤醒，针对本会话的连续交谈靠上下文与声源门禁；无法可靠区分时默认不公开。播放中拾音可靠性及乘客/广播误触发必须实机验证，模型自报置信度不能替代验证。
- 用户未指定视觉改版，无新增配色/品牌选择。不存在阻塞设计的歧义；未开可选专项审查。
