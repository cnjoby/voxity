# 声呐｜说目的，系统完成过程

实施校准（用户后续明确）：只保留一个新版本，不维护旧设备协议；删除本地模拟与 APK 地点素材，使用高德原始 POI ID。模力社区为 `B0K2KHYN77`，七牛公司（人工智能岛19号楼地址）为 `B0FFJSBSGR`，华夏中路与金科路交叉口为 `B0FFHPHNSH`。远程地点仍明确不代表 GPS 到场。完整语音上限已统一设计为30秒，按音频帧上传，超限不截半句发布；下文旧8秒与模拟点位限制是实施前背景。实施与验证以[当前规格](../../../development/spec-voice-first-app.md)为准，本地控制提示与离线停止模型不属于地点模拟素材。

## Foundation

**日常只点一次“开始”，之后不必看屏、不必触屏、不必选择用途。** 想知道什么、想问谁、愿不愿回答，都直接说。Android 继承现有 Compose；ESP32 使用同一语义和本人状态，每次一个主终端。本轮设计异步原声往返，不承诺实时通话。

[DESIGN.md](DESIGN.md)是视觉规范。用户本轮要求覆盖旧版的前置用途选择、用户任务管理和互助开关，保留既有来源、授权与用户状态隔离约束。Android0.2.0与配套后端已实现并部署，见[当前交付与检查](../../../development/voice-first-20261025.md)；代码和模拟器通过不代表真人使用、ESP32或车内声学验收。

首次绑定、系统权限和拾音自检在开始前完成，首次并非一次点击。日常“开始”不要求先选地点：一般助手可先用；必须知道地点的动作才自然澄清。设备不具备可靠本地停止或熄屏拾音时，停在准备状态，显示“免提暂不可用”。

## Information Architecture

| 表面 | 如何到达 / 能完成什么 | 视觉覆盖 |
| --- | --- | --- |
| 启动 | 打开 App；真实状态、一个“开始”、一句公开边界；无模式选择 | [三态预览](mockups/voice-first-states.html)的启动态 |
| 语音会话 | 点击开始后；表达、听回应、追问、分享、拒绝、重听、停止；可熄屏 | 同预览的会话态；对话脚本见 Key Flows |
| 不可用 | 就绪检查失败；说明实际缺失，停车后处理，不伪装正在听 | 同预览的不可用态 |
| 连接与隐私 | 开始前低显著性入口；绑定、权限、数据管理、开发诊断与联调位置 | spine-only，继承原生设置行与系统权限 |

删除“我的”主导航和普通用户“我的任务”页面。任务、邀请、线程、交付和来源是内部持久化对象；用户通过“刚才问的怎么样了”“再听一遍”“不用等了”处理。联调只改变本人选点，手机切换不移动 ESP32。

## Voice and Tone

直接回应事情，不向用户朗读后台流程或菜单。示例表达不构成固定口令。正常成功不播报“识别成功”“发布完成”；用户期待结果、需要澄清或发生有实际影响的失败时才简短回应。

| 用户自然表达 / 情境 | 系统行为与示例 |
| --- | --- |
| “模力社区现在还有车位吗？” | 优先查适用来源；缺少现场信息时可问一次“要我问问在场的人吗？” |
| “帮我问问模力社区的人，还能停车吗？” | 已表达当次公开提问意图，直接执行，不再问“是否公开” |
| “回复他，从哪个门进？” | 唯一有效对象直接发送原声；有歧义才问“你说刚才讲西门的那位吗？” |
| 刚听完相关邀请，直接回答“东门还有三个位置” | 在唯一有效、已实际播出的短对话上下文内自然接话；无需前置“帮我回他” |
| “告诉后面的车友，右边已经能走了。” | 按当次分享意图执行；保留本人原声和实际位置来源 |
| “找个车友聊会儿” | 只匹配自愿参与者；暂无匹配时说明，询问后才可改由助手陪聊，不伪装真人 |
| 一条相关提问需要本人回应 | 一次短邀请：“有人想问模力社区停车情况，你方便答一句吗？”；不回答就跳过 |
| “先别问我”“这次只听不回答” | 本次会话不再收到陌生邀请；自己的问题回应仍按收听意愿处理 |
| “今天别问我” | 按用户所在时区停陌生邀请到当日结束，跨会话保留；不暂停本人请求的回应 |
| “刚才发出去了吗？” | 只按持久化结果回答；未知则“还没核实是否发出，我先查一下。” |
| “停”“安静” | 本地立即停声，不以“好的，已安静”继续占用音频 |
| “退出”“关闭麦克风” | 停止采集并结束；不声称还可以靠说话重开 |

首次准备说明“直接说想知道的事。问人、转告或回应时才把原声发给别人。”同时说明相关原声自动播放、可收到少量相关提问，是否回答由本人决定。旧有“仅私人”“不要邀请”“安静”选择优先保留；有此选择时显示对应一句说明，不能靠新“开始”偷偷覆盖。

## Component Patterns

| 组件 | 行为规则 | 异常 / 恢复 |
| --- | --- | --- |
| `start-action` | 一次开启本人会话与已说明的收听/邀请范围；不弹用途选择 | 设备未就绪不启动；同次重复点击不重复开麦 |
| `readiness` | 结合真实采集、停声、语音服务和连接能力显示就绪，不只看联网 | 权限被收回或进程终止立即失效 |
| `session-status` | 仅镜像正在听、正在回应、等待、安静、结束，使用 `{typography.status}` | 失败必须与实际能力一致，不显示虚假持续聆听 |
| `context-line` | 显示当前一个对象、地点与来源，使用 `{typography.body}`；语音可询问同样信息 | 切换不覆盖旧发送结果，不把问询目标当本人位置 |
| `fallback-controls` | 安静/结束的语音、本机触控和通知共用同一结果；触控仅兜底 | 断网仍能本地停声、关麦；安静后保留本地恢复控制 |
| `setup-row` | 开始前管理连接、隐私、权限、联调；保留 Token 与灵矽配置 | 不在会话故障时要求立即进设置填表 |
| `device-indicator` | 镜像本终端实际就绪、播放、安静、关闭/故障 | 不以指示灯代替口头澄清或可靠停止 |

## State Patterns

内部状态用于恢复与执行，不作为用户菜单。一个会话可等现场回复并继续私人交谈；首期仍只有一个活跃现场问题。

| 状态 | 行为 | 不应发生 |
| --- | --- | --- |
| 未开始 / 首次准备 | 不采集；原生绑定和权限完成后才可开始 | 打开 App 就隐式开麦 |
| 可开始 | 一次主动作；没有位置也可进入一般助手 | 先选五种业务用途 |
| 正在听 | 有界采集面向本会话的发言；普通轮次不反复唤醒 | 将连续车内音频当公共内容 |
| 理解 / 执行 | 语义模型提出动作，规则执行；通常不播流程提示 | 把意图分数当权限或现场证明 |
| 需要澄清 | 一次只问一个关键缺口；两次未听清则说明暂不能处理并保留原意 | 转而朗读列表、要求触屏选项 |
| 等现场回应 | 持久化请求；不阻塞助手，不反复播等待提示 | 每次轮询催答或假称已找到人 |
| 正在回应 / 播原声 | 空闲时播有效相关回应；用户开口优先让路 | 系统/媒体回声变成本人发言 |
| 没有结果 / 超时 | 用户正在等结果时简短说明无现场回应；不循环重新公开 | 把过期素材当现况补答案 |
| 已安静 | 停普通播放、业务提交和对外发布；仅保留本地控制 | 把安静当关麦，或继续向云端提交车内聊天 |
| 临时断网 / 结果未知 | 本地停止有效；恢复先核对原请求，维持原幂等标识 | 重试创建第二份提问、补发旧观察 |
| 电话 / 音频中断 | 暂停；实际采集仍可用才允许语音恢复 | 电话结束就自动重开并公开积压录音 |
| 麦克风撤销 / 进程终止 | 回到未开始，停车重新处理；不能语音恢复已不存在的采集 | 仍显示“正在听” |
| 已结束 | 关闭麦克风并结束会话，保留合法历史及已建立请求结果 | 假称关麦后还能听见“继续” |

## Interaction Primitives

### 让 Agent 选择流程

| 交给 LLM / 决策模型 | 由确定规则执行 |
| --- | --- |
| 理解意图、澄清地点、选择地图/公告/原声等来源 | 身份、音频访问、有效期、实际位置与模拟来源 |
| 选择合适的回应者、内容相关性和提醒时机 | 本人参与意愿、安静、当前音频占用和邀请冷却 |
| 关联最近有效对话、摘要、判断是否还需要追问 | 真实线程关系、幂等、撤销、授权版本和迟到结果丢弃 |
| 从语音提取“以后都记住”等偏好作用域 | 本地停声/关麦优先；未明确授权不扩大可见范围 |

决策任务的发布、邀请和收听结论仍隔离，不能复用一个“相关”分数包办所有动作。模型故障时保留私人状态并说明影响，不自动退回向所有人公开。

### 一句话表达授权，不管理权限表

默认私人询问；明确“问问现场”“分享给车友”“回复他”可授权当次内容与确定对象，正常不二次确认。私人检索查不到不会自动公开。必要的一句“要我问问在场的人吗？”是范围变化，已经明确问人的请求不能再问同样问题。

已实际播放的邀请建立唯一、短时且有效的回应上下文，用户直接说答案即可发送，不必先说“回复”。这属于对明确邀请的自然接话，启动说明已覆盖回应会发送原声；不等于把普通陈述当自动分享。窗口过期、多人发言、旁人声音或对象不明时不公开，必要时只做一句澄清。[ASSUMPTION] 窗口时长需实机验证，不以固定关键词或每句唤醒代替上下文。

“这一路的现场观察都帮我分享”可建立本次有界连续分享；说明范围一次，之后合格观察静默执行。无连续分享授权的普通陈述保持私人。乘客、广播、自播音和来源不明内容不公开，无法可靠区分就不发布。

互助没有页面开关。没有先验拒绝的用户，本次“开始”按启动说明允许少量相关邀请；回答始终自愿。没有时长的“先别问我/这次只听”只管本会话；“今天别问我”按用户所在时区当日结束失效，跨会话保留；“以后都别邀请我”形成长期偏好。只限制陌生邀请，自己的问题回应独立保留。[ASSUMPTION] 试点初值为十分钟最多一次陌生相关邀请，相同邀请不重复，需真人验证。

### 记住上下文，隐藏管理工作

“他/那条/继续”优先指向最近有效、实际播过的对话，只有一个合法对象直接处理；多个对象只问一句区别问题。地点接近不自动构成回复关系。“不用等了”结束对应等待；“有帮助，够了”可结束需求，听完不等于已解决，沉默也不等于已解决。

新现场问题遇到一个活跃问题上限时，只问“换成问东门车位，之前的不等了？”；明确同意才结束旧问题。拒绝后保留旧问题，新问题可继续私人查询，不弹任务管理页。跨会话只在用户主动续问时恢复需求，不自动重播、重发旧内容。

### 插话、安静、结束与恢复

开口先让当前播放暂停，再理解完整发言。“停这条”只停当前声音并延后；“安静”暂停整个会话的普通播放和发布；“不用等了”取消所指需求；“结束/关麦”停止采集。否定和纠正优先于在途动作；已提交的公开内容只能按真实撤回结果说明，不假称别人从未听过。

安静时“继续”由本地控制恢复，重新核对当前授权和有效性；不补发旧音频、不连播过期回应。真正关麦后需下一次点击开始或经验证的物理启动，不能靠语音重开。电话/系统撤销麦克风后的恢复路径取决于实际采集是否存在。

### 来源、长句与失败

真人原声保留；助手摘要、工具结果明确为声呐回应，必要时简短说明来源和时间。过期信息只能说明历史。合成素材仅在明确试听/联调时播放，首条说“下面是合成测试声音”，不用于证明当前路况。模拟位置与合成声音分别标记。

现行单片音频最多八秒，不能截断长句后公开。新体验需要分段、完整语义关联与统一撤销；未实现前，长话保持私有并说明未发送，不能称全流程验收通过。连续两次识别失败后停止追问，不生成猜测的公开请求。

用户主动等待时，失败说明影响和下一步，例如“刚才是否发出还没核实，我先查一下”。语音输出失败不能用屏幕文字代替成功；须提供经验证的本地故障语音或停止会话，不能保持虚假可用。

## Accessibility Floor

- 开始后正常路径零必需触屏、无需看转写、无需背固定口令；熄屏完成提问、回应、拒绝、重听和结束。
- TalkBack 标签与真实状态一致；触控目标至少 48dp，焦点顺序沿阅读顺序，支持字体放大；视觉对比度见 DESIGN。
- 音量准备时校准，不因噪声无限提高；系统保持简短，不能以不停提示弥补识别不足。
- 无法用语音完成时如实标为不可用；停车辅助与数据管理保留原生可访问操作，不成为正常业务的额外步骤。

## Responsive & Platform

| 平台 | 约束 |
| --- | --- |
| Android | 继承 Compose、系统权限和麦克风前台服务；逐机验证锁屏、音频焦点、本地中文停止与回声隔离，进程被杀不假称常在线 |
| ESP32 | 相同语义与访问规则；单独验证内存、VAD、播放参考和本地停止，不因服务端 HTTP 可达就宣称板卡能完成免提 |
| 联调位置 | 准备页选三个点，联调会话内可语音切点/换回真实位置；必须增量实现，当前自动会话尚拒绝模拟点位；ESP32 仍固定模力社区 |

生产中的“帮我问金科路”只改变问询目标；联调中的“切到金科路”才按明确联调状态改变本人模拟位置，目标不明时先澄清。旧 Token、灵矽、服务器地址、用户拒绝偏好、历史和音频保留，不能用清数据完成改版。

## Inspiration & Anti-patterns

保留上一版免提规范的自然接话、原声接续和一次有界授权。覆盖旧版准备页的多用途选择，拒绝把“我的任务”变成语音报菜单，也不把六项权限改成六个口头问题。模型承担编排，不让用户承担系统概念。

## Key Flows

### F1｜小林一次开始，问到模力社区

1. 已完成首次准备的小林打开 App，看到真实“可以开始”，点“开始”，随后熄屏。
2. 他说“帮我问问模力社区的人，现在还能停车吗？”；Agent 解析地点和当次问人意图，无用途选择、无二次公开确认。
3. 请求持久化并寻找合法回应者；等待时仍可问助手其他事。
4. **关键结果：有效现场原声在空隙接回来，小林直接听到回答，无需到任务页或再说播放。**

失败：地点不清只问一句地点；没人回应则如实说明；设备未就绪留在准备页，不能假装开始。

### F2｜阿陈愿意回答，小林自然追问

1. 阿陈已开始且未拒绝相关邀请，听到一次简短停车问题。
2. 在刚播完邀请的唯一有效短上下文里，他直接说“西门还有位”；按邀请上下文把这一段本人原声给对应请求，无须“帮我回复”或选线程。
3. 小林听后说“回复他，东门还能进吗？”；唯一有效对话直接关联并执行。
4. **关键结果：双方用普通说话完成一问一答和追问，原声、对象与来源保持真实。**

失败：阿陈说“这次不了”或不回应就跳过；多个“他”只问一句区别问题；没有合法上下文不随机选人发送。

### F3｜小林让声呐管理等待、分享和偏好

1. 小林问“刚才问的怎么样了”，听到实际等待结果；说“再放一遍”即可重听合法原声，不进入任务页面。
2. 他说“不用等了”，取消该需求；或明确同意以新现场问题替换旧问题。
3. 他说“这一路的现场观察都帮我分享”，建立本次有界范围；后续合格观察静默发布。
4. 他说“今天别问我”，把陌生邀请暂停到本地当日结束；不影响自己问题的回应。
5. **关键结果：没有任务管理页和互助开关，事情、意愿与期限仍被正确保存。**

失败：状态未知先核对，不谎称取消成功；乘客/广播不分享；本次、今天和长期的意愿分别保存，不把暂时选择永久化。

### F4｜小林插话、安静，然后结束

1. 播放期间小林开口纠正地点，音频先让路，再处理完整纠正。
2. 他说“安静”，本地停声并暂停业务提交；网络断开也有效。
3. 麦克风仍可用时他说“继续”，仅恢复当前有效内容；若系统已关麦，则停车后重新开始。
4. **关键结果：说“结束”后采集真正停止，不再以语音唤起假装仍在听。**

失败：在途提交结果未知保留幂等记录，联网先核对；电话、权限撤销与进程终止不自动公开积压内容。

### F5｜小林与 ESP32 同学在模拟点位联调

1. 小林在停车准备进入联调位置并选模力社区，启动时明确提示模拟位置。
2. 完成未来联调语音能力后，他说“听听这里的测试声音”，首条提示合成来源，再播放服务器素材。
3. ESP32 同学留在模力社区发新问题，小林可以语音回应；本人原声注明模拟位置，不标成合成素材。
4. **关键结果：小林说“切到人工智能岛”只切自己；ESP32 不跟着移动，素材和位置来源各自真实。**

失败：当前版本仅支持模拟点位手动回应，尚不能执行本脚本全语音；退出联调先撤销模拟位置再采真实定位，不能以问询目标冒充本人位置。
