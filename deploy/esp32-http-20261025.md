# ESP32 HTTP 联调入口

日期：2026-10-25，Asia/Shanghai。为内存受限设备提供 Sonar 业务 HTTP。

```text
SONAR_BASE_URL=http://122.195.131.106
Authorization: Bearer <原有 SONAR_DEVICE_TOKEN>
```

TCP 80 上仅 `/healthz`、`/v1/*` 直接代理至原应用，包含设备身份、配置、交流会话、邀请、上传与原声下载。
除健康检查外，鉴权、用户隔离、发布授权和音频格式沿用原业务规则。设备使用 bob 的独立凭证，不复用手机或 MCP 密钥。
响应中的音频路径是同源相对路径，继续用 HTTP 业务基址拼接，并带设备 Authorization Header。
固件不能收到 301/308 后自动带凭证跨域或升级回 HTTPS；本入口的业务检查均验证无重定向。

HTTP 会明文传输设备 Token 和音频，仅供本轮联调。Android 默认地址仍为 HTTPS；
Linx OTA/WSS 和云端 MCP 继续使用各自 HTTPS/WSS 地址。这个入口不会减少灵矽 WSS 连接的 TLS 开销。
音频应分块读取/写入，避免将整段 WAV 或整个 multipart 请求体同时复制进内存；
乐鑫提供 [HTTP 流读写接口](https://docs.espressif.com/projects/esp-idf/en/stable/esp32/api-reference/protocols/esp_http_client.html#http-stream)，固件需按已锁定的 SDK 版本实现。

## 关闭 HTTP 业务入口

从模板和实际 Caddyfile 删除显式 `http://{$SONAR_PUBLIC_IP}` 块，保留原 HTTPS 站点；
先用 `SONAR_PUBLIC_IP=122.195.131.106 /usr/local/bin/caddy validate --config /etc/caddy/Caddyfile` 校验，
再 `systemctl reload caddy`。随后核对 HTTP 业务路径已恢复跳转 HTTPS，HTTPS 健康及鉴权仍正常。
也可在确认没有后续代理修改后恢复上述备份；不要直接覆盖后来新增的代理配置。
